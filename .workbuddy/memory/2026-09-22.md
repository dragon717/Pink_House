## 补录上新 · 给既有商品补价格（重复不再阻断）

- 根因：`ShopCatalogDraftStore.publish`（ShopCatalogOps.swift）命中 `findExistingProduct`
  时对非现货草稿直接抛错（"已收录，预约记录请直接编辑既有商品"）。
  但补录场景里商品常常已在 Catalog、甚至已被收进心愿/尾款/衣橱，补录的目的正是补价格 → 拦截等于价格永远补不上。
- 修法：命中既有商品一律只追加本次 SaleEvent（预约 / 现货都放行），商品本体（名称/分类/图片/规格/尺码表）
  仅在草稿携带新资料时补全，永不因"重复"抛错；摘要区分「追加预约价记录 / 追加现货价记录」。
- 连带修复（`CatalogPriceArchive.init`，ShopCatalogModels.swift）：`Sequence.max(by:)` 在并列时保留**先出现**的元素，
  补录记录通常没有 startAt（全为 distantPast），导致新补价格被旧记录盖住、商品页怎么补都不变。
  改为显式 `(startAt, 数组下标)` 比较 —— 时间晚优先，时间相同取后追加的那条（仍保持「记录只追加不覆盖」）。
- 商品详情页 `ShopCatalogProductDetailView.priceArchiveCard`：预约价 / 现货价 / 定金 / 尾款全部占位展示，
  定金与尾款同排并列，缺失统一兜底「暂无」（不再强行 `deposit ?? 0`，也不留空白）。
- 单测 `ItemManagerTests/ShopCatalogPriceSupplementTests.swift` 6 用例全过；

## 价格修正语义调整：留空 = 清除该价格

- 用户反馈：修正弹窗留空原本表示「不修改」（nil 跳过该字段），但运营预期是「没有这个价格」
  ——留空应清除原价，不能因空就跳过更新。
- 语义改为**完整快照**：
  · 修正弹窗 onAppear 按**当前生效值**（修正优先、否则历史推导）预填四个字段；
    用户删掉某字段再保存 = 明确清除该价格；未改字段带预填原值提交，天然保留。
  · `correctCurrentPrice`：nil = 清除（不再「跳过」）；删除 `noChange` 错误（全空 = 全部清除，
    合法操作）；新增对账拦截——预约价留空时定金/尾款必须一并留空（失去对账基准），
    否则抛 depositBalanceMismatch。
  · `CatalogPriceArchive`：correction 存在时四个 current* **逐字段对号入座**，修正值 nil =
    已清除（展示「暂无」），**不回退**历史推导；只有 correction == nil 才回退。
    init 里 `correction?.isEmpty == true ? nil : correction` 的吞空逻辑必须删掉
    （否则「全部清除」永远不生效）；`CatalogPriceCorrection.isEmpty` 已随之删除。
- UI（ShopCatalogPriceCorrectionSheet）：占位文案「留空 = 不修改」→「留空 = 清除」，
  footer 与横幅同步说明「留空 = 清除，想保留的字段请保留预填数字」。
- 测试：PriceFlowSeparationTests 改造 + 新增（全空清除、单清现货、清预约价留定金拦截），
  价格三套件 33 用例 0 失败。
