## 品牌上新资讯功能方案调研

用户提出想做联网功能：让用户及时看到品牌新出的裙子、搭配资讯、新上架商品。产出 `docs/品牌上新资讯功能方案.md`。

核心结论（联网调研所得，后续沿用此口径）：
- 三坑「上新」不是商品上架事件，而是 3-6 个月时间线：图透 → 定金 → 尾款 → 出货 → 再贩。定位应是「品牌上新订阅 + 节点提醒」，不是商品聚合页。
- 微博开放平台 V3.0 需企业资质 + Credit 按量计费，个人无免费额度；小红书笔记 API 永久不对个人开放（仅企业合作方）；**小红书不要做自动采集**。
- 淘宝客 API（阿里妈妈）个人可申请，是唯一低门槛合规商品数据源，可拿转链做 CPS。
- RSSHub 自建可覆盖微博官博/B站/超话，`/weibo/user/:uid` 需配 Cookie，`/bilibili/user/dynamic/:uid` 不需要。属灰色地带，2024 年曾濒临停摆。
- 阿里妈妈明令禁止用淘宝客 API 数据训练 AI 大模型，LLM 只能做字段抽取。
- 技术路线：复用现有 `NoticeCloudKitService`（Public DB 公告 CMS），新增 `BrandFeedItem` record type，CloudKit 下发，不自建后端。
- 建议第一期纯人工运营验证需求，不上自动化。

### 重要发现：项目已有品牌内容采集管道（方案已据此修正）

`tools/time_hall/` 下已有一整套 V3 导入器，覆盖的正是本次需求：

- `import_news_batch.py` — 721 篇 News，发售/联名/限定/展会事件（= 品牌新裙子 + 资讯）
- `import_commerce_batch.py` — 当前商品 + OUTLET，原价/折扣价/库存（= 新上架商品）
- `import_coordinate_batch.py` — 150 套官方造型 + 搭配说明（= 搭配资讯）
- `import_curated_commerce.py` — 四大日牌官网：Angelic Pretty / BABY(含 AATP) / Juliette et Justine / Wunderwelt FLEUR
- `content_batches.json` 是批次 source of truth；`scrape_pinkhouse_news.py` 是已禁用的 V2 遗留脚本

瓶颈在于：管道是「人工跑 → 写死进 App Bundle `catalog.json` → 随版本发布」，用户拿到的是版本级新。
所以正确做法不是建新管道，而是升级为「定时跑 → 增量 diff → CloudKit 下发」。

CloudKit 侧现成资产：`docs/TIME_HALL_CLOUDKIT_UPLOAD_PLAN.md` 已定义 `TimeHallEntry`（含 status/sourceKind/moderationNote）；`NoticeCloudKitService` 有 Public DB 容器 + adminIDs 审核模式；`docs/SKIRT_MARKET_DEEPSEEK_IMPORT_DEMO_PLAN.md` 有 DeepSeek 结构化链路且 `sale_intent` 已含 deposit/final_payment。

覆盖缺口：现有管道只覆盖日牌官网，不覆盖国牌（微博/淘宝/小红书），国牌需新建采集。
