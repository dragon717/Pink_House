## 需求：商品改名不生效（2026-09-24，用户三张截图）

**用户原话**：「修改名称后，相关信息未发生任何变化。请排查并修复名称修改功能……」

**复现链**（截图页确认是 `ShopCatalogSeriesProductsView`，系列「蜜糖邦尼兔联名系列」）：
长按「背心裙 [黄色]」→ 菜单「编辑基础（名称/分类）」→ 弹窗名称改成「黄色蜜糖邦尼背心裙」
→ 保存 → **点菜式选购页标题仍是「背心裙」**。

**根因（两处叠加，缺一不可）**：
1. 所有标题只读 `designName`（`ShopCatalogTitleResolver` → `ShopCatalogSameDesignGrouper.designName(of:)`）；
2. 发布路径**无条件**把 `designName` 写成非空显式值（`resolveDesignName` 永不返回 nil，
   `baseName` 兜底回退整名）→ **`name` 被永久遮蔽**，派生分支永不执行；
3. 两条写入路径（`upsertEntity` 基础编辑 / `updatePublishedProduct` 深度编辑）
   都只写 `name` + `category`，**没有一个字节碰 `designName`**。
→ 改名写进一个没有任何界面读的字段，所以「什么都不会变」。

**为什么不能「顺手也让弹窗改一下 designName」**：`designName` / `category` 是**款式身份**
（`designKey` = 品类|款式名；`styleKey` = 系列|品类|款式名 = `CatalogStyleProfile.id`；
尺码表共享范围也按 `designKey` 现算）。只改一色 → 「2 色一款」当场**拆成两个单色款**
+ 款式档案（面料/款式描述）孤儿 + 尺码表范围塌成 1 行。

**修复**：新增纯逻辑模块 `ShopCatalogProductRename`，改名收口成**款式级**计划；写入口
`renameProduct(productID:newName:newCategory:)`；`updatePublishedProduct` 共用同一份计划。
七条口径 + 弹窗预览文案见 `RULES.md`「商品改名 = 款式级」一节与
`docs/商品改名未生效_根因与同步修复_需求实现说明.md`。
