## 预约价格表：标准模板 + 结构与排版规范（承接 10-01 尺码表那一轮）

用户原文：「价格表也请按同样的方式处理：请为我提供一个标准的价格表模板，
明确其整体结构、需要包含的字段（如项目名称、单价、数量、单位、金额、备注等），

### 截图里的失败是怎么来的（两处叠在一起）

Mac「系列价格表」卡片，结论 **预约价格表识别失败**。输入是：

```
单位：   （空）
列名：   （空 —— 显示的是 placeholder）
数据行： 款式=,预约价,定金,尾款
        花店 花束发带=139,27,112
        …
```

- **列名框空着**，而把**列名行**贴进了数据行 ⇒ 列 0 个、数据行 6 行 ⇒
  「至少要有列名与一行数据」不过。
- 就算把第一行当数据行读，它是 4 个值，而下面每行只有 **3 个值** ⇒ 个数不齐。
- 另外那行 `139,27,112` **少一个价格槽**：领域模型有四个（预约价/定金/尾款/现货价），
  他这套只有三个（缺现货价）。

### ⭐ 顺带查出的三处「隐式规范互相矛盾」（都改了）

界面上的示例文案就是用户照着抄的规范。**同一个界面上两句示例对不上，用户照哪句都可能失败。**

| # | 位置 | 矛盾 | 现在 |
|---|---|---|---|
| 1 | Mac 价格表卡 | placeholder 举例 **4 列**（含现货价），紧挨着的「每一行」提示只写 **3 列** | 两处都读 `CatalogChartTemplate.PriceChart` |
| 2 | Mac 价格表卡 | 「单位（如 **cm / inch**）」—— 那是**尺码表**的长度单位，从旁边那张卡抄来的 | 改「单位（如 元 / ¥）」，并注明是金额单位 |
| 3 | Mac 尺码表卡 | placeholder 举例 **3 列**，提示只给 **2 个值**（`S = 80, 78-83`） | 两处都读 `CatalogChartTemplate.SizeChart` |
| 4 | iOS 粘贴面板 | 价格表 `example` 列名行 **4 列**，第二行 `蝴蝶结半裙:268,80,188` 只有 **3 个值** | 由共享模板派生（只做「等号→冒号」替换） |

第 4 条在 iOS 上恰好能混过填写率门禁（7/8 = 0.875 ≥ 0.4），
所以**不会在 iOS 报错**，但用户把同一段贴进 Mac 就会撞「值个数与列名不符」——
正是 10-01 那个报障的形态。**这类「本地不报错、跨端才炸」的示例最阴**。

## 把「价格表上传」搬进系列上新向导 S2（同一轮，用户接着提的）

用户原文：「请把价格表的上传功能集成到当前页面中，实现文件选择与上传操作，
上传成功后展示或解析价格表内容，并处理上传失败、文件格式不支持等异常情况。」
（截图是向导 **S1「店家与系列（必填）」**那张卡 —— 意思是「就在我正在用的这个向导里」。）

### 落点：**S2·系列资料**，不是 S1

价格表是**系列级资料**，S1 只管「选店家 + 选系列」，S2 的标题就是「系列资料」。
为防止下次又出现「功能改到哪去了」，S1 的「归属摘要」卡里**加了一行指路**：
「系列价格表在下一步「S2·系列资料」里上传图片或录表格 —— 本页只做选择，不收内容。」

### ⭐⭐ 新增一条数据损坏级的规则：**切系列必须重载价格表块**

向导工作副本 `OpsSeriesEntryDraft` 是**长期持久化**的（`OpsCatalogDraftRecord.seriesEntryJSON`）。
给 S2 加了系列级字段之后，如果在 A 系列填/传了价格表，然后在 S1 把「系列」改成 B 系列，
**提交时会把 A 的价格表原样写进 B** —— 全程没有任何报错、界面上也看不出异常。
所以 `seriesChoice` 的 setter 里必须调 `reloadPriceChartFromSelectedSeries()`：
- 目标系列已有价格表 → `declaresPriceChart = true` 并载入单位/列名/行/原图；
- 没有价格表、或选了「＋ 新建系列…」→ **清空**，绝不把上一个系列的带过去。

⚠️ 只在**用户显式切换系列**时重载，**不做 `onAppear` 自动装载** ——
那会把手打了一半、还没提交的向导内容用系列上的旧值覆盖掉（违反「失败不丢输入」）。
⚠️ 同一形状的既有隐患（本轮**没动**，只记录）：`coverAssetID` 也是向导里的系列级字段，
切系列时同样不会重载 → 「在 A 选的封面会被写进 B」。要修就照上面这段一起修。

### `declaresPriceChart` 显式开关（与 `declaresPhase` 同一个理由）

「这一项我没填」和「我要把它清空」在数据上长得一样（都是空字符串）。
没有开关，走一次向导就会**静默清掉**系列上已有的价格表。所以：
- 关着 → 提交**一个字都不写**（`applySeriesPriceChartFromWizard` 直接 return true）；
- 开着 → 写结构化列行 **或** 只有原图（`CatalogPriceChart.hasStructuredContent == false`
  是**合法状态**，客户端详情页退化成展示原图，不是容错）。

### 三类提示必须分开（仓库铁律的又一次应用）

| 情形 | 提示 |
|---|---|
| 选择被取消 | 什么都不说（**不是**失败） |
| 全部失败 | 卡片内逐条列原因 + 置 `lastError`（顶部横幅橙字） |
| 部分成功 | 「已上传 N 张」**和**「M 个文件没能上传」**两句同时在**卡片里 |
| 格式不支持 | 「`xxx.xlsx`：格式不支持。价格表原图只能是图片（PNG / JPEG / HEIC / TIFF / GIF / BMP），不支持 PDF、Excel、Word 等文档。」 |

⭐ 文件选择器**故意放宽到 PDF / 表格 / 文本**（`OpsWorkspace.priceChartPickerTypes`）：
很多人是拿 Excel 排好价格表再导出的，系统面板里灰掉一片只会让人以为功能坏了。
选中后由 `isSupportedPriceChartFile` 拦下并给出可执行的拒绝。
支持格式清单、面板过滤器、导入前校验**共用 `priceChartFileTypes` 一份**（三处写三遍必然分叉）。

「缺图三道防线」条目）：

- **根因不是「图丢了」，是「引用」与「文件」在交接链路上被当成两件事，且没有任何一层
  做过强制对账**：iOS 导出缺图→toast 提示后**仍照打包**（`ShopCatalogOpsView`:
  `toast = "已打包 N 张图片，M 张缺失"` 但 tar 照写）；Mac 导入缺图→提示后**仍照导入**；
  直到发布前门禁才第一次强制对账 —— 此时已跨 2 台设备 3 次交接，源头早不在现场。
- **「警告不等于处理」**：下游照单全收的警告 = 把风险传给下一环。
- 三道防线：①**防**在出口（导出端缺图拒绝打包 / 包内 manifest 声明不完整）；
  ②**知**在入口（导入/换机立即对账，「缺 N 张」常驻，不等发布才炸）；
  ③**补**靠账本（发布产出的 `bridge/publish-*/output/media.json` 有
  fileName/contentHash/recordName，**只当次用、没沉淀** → 持久化成媒体账本后，
  本地文件丢了也能把引用回填成 `thmedia:`，图不用重传）。
- **门禁不放宽**：绝不提供「忽略缺图继续发布」开关（静默丢图最糟）。
- 用户侧分三档：自助（回源重导+重导入）/ 半自动（账本回填，需先实现③）/ 只能重传重拍。

## 双向媒体同步（用户需求，22:05）—— 勘察结论与设计要点

- ⚠️ **建议①（导出端缺图拒绝打包）被用户否掉，且他是对的**：「没有图」可以是
  **合法终态**（系列就是没价格表原图 / 商品暂时没图）→ 不能一刀切拒绝。
  正确口径是区分「从未有过图（合法/待补）」与「本该有图却丢了（异常）」，
  区分不了就不该禁 —— 别再提「缺图拒绝打包」。
- ⭐ 用户要的是**三向合并**：远端有/本地无 → 拉下来；远端无/本地有 → 传上去；
  本地删了 → 远端标记删除。
- ⭐⭐ **对齐键不能是文件名**：两端命名体系不同（iOS `img-XXX.jpg` vs 云端
  内容哈希 `thmedia:<hash>`）→ 必须按 **(field, entityID)** 对齐
  （`ShopCatalogMediaReferences.all` 已带 field/entityID/productID）。
- **勘察事实**：① 目录**没有媒体墓碑**，只有 `removedShopIDs/removedSeriesIDs/
  removedProductIDs`（新字段一律 Optional）；② 拉回+条目级对齐能力已存在且完好：
  `OpsWorkspace.alignCatalogToPulledContent` + `ShopCatalogReconcile.align`
  （线上有→加 / 同 id→线上覆盖 / 本地多有→移除），只是面板删除后**无 UI 入口**；
  ③ ⭐ **R5 未修是这条路的前置阻塞**：采用 thmedia 引用后下一次发布会被
  `build_release.py:383` 判 media.reference.missing（假错误）→ 不修 R5，
  「拉回合并 → 发布」仍然发不出去。
- 待用户定：①范围（只媒体引用 vs 条目级整份对齐，后者违反其早前「不拉回整份目录」）；
  ②采用远端引用时是否同时下载字节（只改引用 = 发布能过但本地预览仍空）。
