## 裙装价值 — 改为按付款口径（只计已付定金）

需求确认: 用户选择"只计已付定金"，即裙装价值与总价值对齐付款口径，两者差异只剩"是否含小物与邮费"。

原问题: `dressValue` 用 `price * stock`，除已售出外一律按吊牌全款算 —— 定金尾款还没付清的商品也被按全款计入，虚高。

关键机制（读代码确认，勿再猜）:
- `reservationKind`: `status == .offShelf` → `.sold`；非定金模式 → `.owned`；定金模式且 `balance == 0 && deposit > 0` → `.fullPaymentReservation`；否则 `.depositPlan`
- 付尾款动作 = `WealthSavingLedger.markFinalPaymentCompleted`（Clothing.swift L806）：**只把 `isDepositPlan` 置 false**，不动 `deposit`/`balance`/`price`，也不重置 `condition`（付完尾款后 condition 仍残留"待付尾款"）
- 定金商品保存时 `price` 会被回推为 `deposit + balance`（ClothingEditView L2467、depositPlanAmountResolution），所以 `price` 不为 0

改法（模型层建单一口径，避免两处漂移）:
1. `ItemManager/Clothing.swift`: 新增 `dressValueAmount`，与 `wardrobeValueAmount` 并列
   - `.owned` → `money(price) * stock`
   - `.fullPaymentReservation` / `.depositPlan` → `money(deposit) * stock`（不含小物定金、不含邮费）
   - `.sold` → 0
2. `WealthViewModel.swift`: 新增 `sanitizedDressValueContribution(for:)`，与 `sanitizedWardrobeContribution` 对称（走 `FinancialDataSanitizer.aggregateMoney`）
3. `WardrobeView.swift`: `WardrobeClothingSnapshot` 新增 `dressValueAmount` 字段（构造点唯一，已 grep 确认）；`statsSummary` 改用 `snapshot.dressValueAmount`
4. `WardrobeStatisticsDetailView.swift`: `dressValue` 改用 `clothing.dressValueAmount`
