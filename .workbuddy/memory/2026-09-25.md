**现状事实（已核对代码）**

  `ShopCatalogStore.rebuildMergedCatalog()` 做合并：同 id 整体替换、`saleEvents` 只追加、

  设计文档里写的 `TimeHallPublicCloudReader` / `TimeHallPackCache` / `TimeHallMediaCache` /
  `TimeHallPublicationModels` **在仓库里不存在**（commit d84d983d「移除时光馆旧馆与仲夏物语模块」）。
  即：**消费端 Swift 读取层为零，Mac 发布端 python 流水线完整**。
- `tools/time_hall/publication/`（build/validate/publish/verify/rollback + protocol.py）是通用
  分片发布协议，`docs/时光馆_店家上新模式重构实现方案.md` §1.3 明确「保留作为未来公共 Catalog

- 容器 `iCloud.bugod2.ItemManager`（与 Notice 公告同容器，entitlements 已声明）。

**两个既有缺陷（本次新发现，未修）**
1. `docs/TIME_HALL_CLOUDKIT_CONSOLE_SETUP.md` §3 与 `publication/README.md` 的「凭证」一节
   写「在 Console 建 key → 下载私钥 PEM」——**与 Apple 口径相反**。Apple 的正确流程是：
   本地 `openssl ecparam -name prime256v1 -genkey -noout -out eckey.pem` 生成密钥对，
   **只把公钥**（`openssl ec -in eckey.pem -pubout`）粘进 Console 的 API Access →
   Server-to-Server Keys，保存后 Console 回填 Key ID；私钥永不离开本机。
2. `publish_adapters.sign_request` 只签 `date_bytes + b":" + body`，
   而 Apple 规范是 `[date]:[base64(sha256(body))]:[URL subpath]` 三段。
   README 自己也承认「未经真实环境验证」——真机联调前必须先修这里。
   （另：设计文档 §6.3/§6.4 的 THDataPack/THMedia 字段名与实现不一致，
   实现 + Console 配置清单为准：`partitionID/releaseSeq/sha256/byteCount/asset`。）

**推荐方案**：运营发布通道（Mac，s2s 凭证写）+ 设备只读消费通道；普通用户对
THRelease/THDataPack/THMedia 零写权限（World 只读）。v1 建议把覆盖层整包当
单个分片（partitionID 形如 `pink-house/shop-catalog/all`）发布，客户端下载后
直接当作 `overlayCatalog` 走现有合并规则。
**关键坑**：`CatalogAsset.originalURL` 里的 `local:<文件名>` 引用跨设备无效，
运营上传图必须改走 THMedia，客户端要建立 `mediaKey → contentHash → 本地缓存路径` 解析。

## 需求：切换颜色后点菜页分区乱跳（2026-09-25，用户三张截图）

**现象**：美乐蒂蜜糖邦尼系列的点菜式选购页，衬衫/内搭/开衫/外套四个分区的先后顺序
在 02:12 与 02:13 的三张截图里各不相同（衬衫,内搭,开衫,外套 / 外套,内搭,开衫,衬衫 /
外套,开衫,衬衫,内搭），用户归因为「切换颜色导致重新排序」。

**根因**：与颜色切换**无关**。`ShopCatalogStore.categories(inSeries:)` 用
`Array(Set(products.map(\.category)))` 派生非固定品类（衬衫/内搭/开衫/外套都是
自定义分类，不在 `canonicalCategoryOrder` 里）的顺序 —— Swift `Set` 遍历序取决于
**进程级随机哈希种子**，每次冷启动都换一个排法。乱序恰好在用户反复进出页面 /
重启调试（切颜色常伴随这些动作）时被观察到，造成了「切颜色 → 乱序」的错觉。
规则早已预警过（数组是录入序不是字典序），这次是 Set 版的同类事故。

**修复**：`categories(inSeries:)` 改为三段确定性顺序 —— 固定品类（除「其他」）在前 →
自定义分类按商品**首次出现序**（catalog 数组持久化录入序，跨启动稳定）→「其他」垫底。
注释写明根因与口径。

**回归锁**：`ShopCatalogStoreTests` 新增 2 例：
- `testSeriesCategoriesCustomOrderIsEntryOrderNotSetOrder`：录入 外套→衬衫→内搭→开衫→其他→JSK，
  必须输出 `["JSK","外套","衬衫","内搭","开衫","其他"]`，重复调用 + 第二个同数据实例结果一致。
- `testSeriesCategoriesIgnoresArchivedProducts`：归档商品所在分区不出现。
首跑时我自己把期望值写错（把内搭排第一），实现其实是对的——已修正期望。
