## 批次录入整批归属整合（同日凌晨，用户需求驱动）

- 用户需求：同一系列多单品整合到同一条链路展示，不要单品与链接一一对应的分散结构。经确认方向 = 运营端录入整合（用户端系列聚合本已存在：店家主页/上新首页卡片以系列为单位，系列详情页就是单一入口）。
- 根因：CatalogBatchEntrySession 早有整批同店同系列字段、createBatch 也会写入草稿，但 UI 从未提供设置入口，批次行不可点 → 运营只能逐条草稿手动补系列 = 分散结构根源。
- 落地：ShopCatalogBatchDetailView（整批归属区：既有/新建店家 + 既有/新建系列+年份季节，「应用到整批 N 条单品」；本批单品按系列分组展示）；DraftStore.applyBatchAttribution（同步会话+未发布草稿，published/archived 不回写）；OpsView 批次行 onTapGesture → sheet，标题尾缀「未指定归属」提示。
- 验证：ShopCatalogBatchAttributionTests 3/3（整批同步+会话持久化/发布条目跳过/同系列聚合发布=1 系列 3 单品多品类齐全）；全量回归 52/52 绿。
