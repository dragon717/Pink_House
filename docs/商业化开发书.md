# Pink House 商业化开发书

## 项目概述

Pink House 是一款萌宠养成类 App，采用"喵币"虚拟货币体系进行商业化。用户通过 IAP 购买喵币，再用喵币兑换食物、主题、VIP 服务等虚拟物品。

---

## 一、内购商品配置（已落地）

### 1.1 喵币档位（消耗型项目 Consumable）

| 商品ID | 价格 | 基础喵币 | 赠送 | 首充双倍 | 实际获得 |
|--------|------|----------|------|----------|----------|
| com.pinkhouse.app.meowcoin_60 | ¥6 | 60 | +6 (10%) | 120 | 首充120 / 日常66 |
| com.pinkhouse.app.meowcoin_120 | ¥12 | 120 | +12 (10%) | 240 | 首充240 / 日常132 |
| com.pinkhouse.app.meowcoin_300 | ¥30 | 300 | +30 (10%) | 600 | 首充600 / 日常330 |
| com.pinkhouse.app.meowcoin_500 | ¥50 | 500 | +75 (15%) | 1000 | 首充1000 / 日常575 |
| com.pinkhouse.app.mcoin_1280 | ¥128 | 1280 | +320 (25%) | 2560 | 首充2560 / 日常1600 |
| com.pinkhouse.app.mcoin_3280 | ¥328 | 3280 | +1148 (35%) | 6560 | 首充6560 / 日常4428 |

**首充规则**：每个档位独立计算首充双倍，首次购买该档位享受双倍，之后享受赠送比例。

### 1.2 VIP 兑换规则

| 项目 | 价格 | 时长 | 说明 |
|------|------|------|------|
| VIP 会员时长 | 66 喵币 | 1个月 | 在会员中心手动兑换，不自动续费 |

**注意**：VIP 不单独走苹果订阅，必须先购买喵币，再在 App 内消耗喵币兑换。

### 1.3 App Store 兑换码礼包（消耗型隐藏商品）

| 商品ID | 类型 | 发放内容 | App 内入口 | 说明 |
|--------|------|----------|------------|------|
| com.pinkhouse.app.offer.bonus_888_66666 | Consumable | 888 喵币 + 66666 鱼币 | App Store 优惠码兑换页 | 隐藏商品，不在喵币商店售卖，仅通过 App Store Connect Offer Codes 兑换 |

**兑换规则**：
- 使用 App Store Connect 的 In-App Purchase Offer Codes，不使用旧版 IAP Promo Codes。
- 创建 Free Offer，并生成 One-Time Use Codes；每个码只能兑换一次，同一用户对同一个 Offer 只能兑换一个码。
- 不使用 Custom Code，因为 Custom Code 是多人共用同一个码，不满足“一人一码”。

**App Store Connect 配置**：
1. Apps → Pink House → In-App Purchases，新建 Consumable。
2. Product ID：`com.pinkhouse.app.offer.bonus_888_66666`。
3. Reference Name：`兑换码礼包 888喵币 66666鱼币`。
4. Display Name：`兑换码专属礼包`。
5. Description：`通过官方 App Store 优惠码兑换后获得 888 喵币和 66666 鱼币。`
6. 审核通过后，在该 IAP 的 Offers 中创建 Free Offer：`gift_888_meow_66666_fish_v1`。
7. 在 Offer 下生成 One-Time Use Codes，下载 CSV 后按“一人一码”分发。

## 二、技术架构（已落地）

### 2.1 验证方案选择

**当前方案**：StoreKit 2 原生本地验证（纯客户端验证）

**文件位置**：
- `ItemManager/Services/IAP/StoreManager.swift` - 购买管理
- `ItemManager/Services/IAP/IAPServerManager.swift` - 历史验证封装（现仅保留喵币发放逻辑）
- `ItemManager/Services/IAP/IAPProduct.swift` - 商品定义

**流程**：
```
用户点击购买 → StoreKit 2 调起支付 → Apple 验证 →
StoreManager.processTransaction() → 本地发放喵币
```

兑换码礼包流程：
```
用户打开 App Store 优惠码兑换页 → 输入 One-Time Use Code →
StoreKit 2 收到隐藏商品交易 → StoreManager.processTransaction() →
本地发放 888 喵币 + 66666 鱼币
```

### 2.2 首充双倍实现

**核心逻辑**：`FirstDoubleBonusManager`
- 使用 `MeowCoinAccount.firstPurchaseCompletedByProduct` 记录每个档位的首充状态
- 键为 productID，值为是否已完成首充
- 各档位首充状态独立计算

### 2.3 数据存储

**当前方案**：本地存储（UserDefaults + SwiftData）

**存储内容**：
- 喵币余额：`MeowCoinAccount.storageKey`
- 首充状态：`firstPurchaseCompletedByProduct` 字典
- 购买历史：`IAPPurchaseRecord.storageKey`

**注意**：当前为本地验证，数据存储在设备本地。如需多设备同步，后续需迁移到云端。

## 三、测试方案（已落地）

**位置**：`IAPTestManager.swift`

**功能**：

## 四、审核准备

### 4.1 App Store Connect 配置清单

- [ ] 签署"付费应用程序"协议
- [ ] 创建 6 个喵币档位（消耗型）
- [ ] 创建 1 个兑换码礼包隐藏商品（消耗型）
- [ ] 为隐藏商品创建 Free Offer 和 One-Time Use Codes
- [ ] 配置沙盒测试账号
- [ ] 准备审核截图（展示喵币使用场景）

### 4.2 审核话术（VIP 说明）

> "Our application's 'VIP' feature is designed as a flexible, on-demand service. Users can purchase 'Meow Coins' via IAP and decide when to exchange them for specific service durations (e.g., 7 days or 30 days) based on their pet's growth stage. Since this is not a recurring monthly commitment but a one-time service activation triggered by the user, the Consumable IAP model (Meow Coins) provides the most transparent and user-controlled experience."

### 4.3 注意事项

1. **文案规范**：使用"获取"、"购买"，避免"充值"
2. **付费路径说明**：VIP 为喵币兑换型特权，不提供单独订阅入口
3. **隐私政策**：购买页面需提供隐私政策链接
4. **虚拟物品说明**：明确告知虚拟商品不支持退换

## 五、后续优化建议

### 5.1 安全性增强（可选）

当前为纯客户端验证，存在越狱插件风险。如需增强安全性：

**方案 A**：接入 RevenueCat / Adapty（第三方服务）
- 优点：无需自建后端，完整的支付状态管理
- 缺点：月流水超过 $10k 后收费

**方案 B**：自建简单后端验证
- 使用 Firebase Functions 或 Cloudflare Workers
- 调用 Apple App Store Server API 验证交易
- 代码量约 50 行，安全性大幅提升

### 5.2 多设备同步（可选）

当前数据存储在本地，如需多设备同步：
- 迁移到 CloudKit 公有数据库
- 或使用自建后端 + Apple ID 绑定
