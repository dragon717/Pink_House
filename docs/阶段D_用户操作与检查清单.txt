正式内容：操作与检查清单

打开手机上本次安装的版本，先看看结果：
□ 打开「店家上新」，下拉刷新，等刷新结束。
□ 找到「阶段D手机验收店家」。店家名称、图标应正常。
□ 店家简介应有「阶段D电脑发回，手机应能看到」。这句话来自电脑，可以确认手机收到了电脑的修改。
□ 打开「阶段D手机验收系列」，封面应能显示。
□ 「阶段D手机验收商品（非售卖）」已在检查中删除，不应再出现。
□ 关掉应用再打开并刷新，删除的测试商品仍不应出现，其他内容正常。

这轮用的是专用测试样本。手机上原有的三份运营资料已核对，和检查前一样；日常内容仍由你在运营工具里主动上传。

平时可以照这个顺序检查：
录入或修改 → 同步更新并上传并等到成功 → 手机和电脑都刷新 → 检查文字、图片和删除结果

日常从手机上传：
1. 打开「我」→「运营工具」，录入或修改商品。整批归属会带入新添加的单品。
2. 新草稿依次点「提交」→「审核通过」→「发布」，完成本机入库。
3. 回运营工具底部点「同步更新并上传」。自动取回远端、合并新增与修改；有冲突时选择冲突字段的来源。
4. 等到「已发布并验证成功」；上传任务应显示店家、系列和商品名称。
5. 手机「店家上新」下拉刷新，电脑取回同一环境，检查名称和图片一致。

日常删除：
1. 在「运营工具」打开「店家 / 系列 / 商品管理（编辑、归档、删除）」。
2. 进入商品所属系列，找到要处理的商品，通过更多按钮选择删除并确认。
3. 回运营工具，再点「同步更新并上传」，等到明确成功。
4. 手机、电脑都刷新。该商品应消失，其他商品保留。
5. 若应用提示不能删除，只能归档，就按提示选择归档。

如果你以后重新用 Xcode 安装手机版本：
菜单 Product → Scheme → Edit Scheme，选择左边 Run，再打开 Info。
将 Build Configuration 选成 Release，关闭这个窗口后再运行到手机。
本轮已安装的版本连接正式内容；平时默认的 Debug 连接试用内容。

普通使用者只需要浏览、下拉刷新和看图，不需要进入运营工具。
不需要为了检查而卸载应用，也不需要清空手机上的个人资料。
