# 年月字段与价格表多图与时光馆加购图片_需求实现说明

> 2026-09-24 需求（三项）：① 基础信息「年份」→「年月」并支持两种录入格式；
> ② 预约价格表恢复图片上传入口并支持一次多选；③ 从根源修复「时光馆加购 →
> 衣橱不显示图片」。本文记录实现落点、口径与验收结果。

---

## 一、「年份」→「年月」

### 存储口径

`CatalogSeries` 新增 `var month: Int? = nil`（`ShopCatalogModels.swift`），与既有
`year: Int?` 配合表达年月粒度。

- **必须 Optional**：合成 `Decodable` 走 `decodeIfPresent`，旧 JSON / 已发布覆盖层
  缺键自动置 nil，**零迁移**（`salePhase` / `reservationEndAt` 同款模式）。
- 解析 / 校验 / 展示的唯一口径：`CatalogYearMonthText`（新文件
  `ItemManager/Services/ShopCatalog/ShopCatalogYearMonth.swift`）。

### 录入与校验（`CatalogYearMonthText.parse`）

| 输入 | 结果 |
|---|---|
| `2026-10` | year=2026, month=10 |
| `2026年10月` | year=2026, month=10（个位月不带前导零也可：`2026年3月`） |
| `2026` | year=2026, month=nil（**纯年份仍有效**——存量系列打开编辑页回填
  `"2026"` 后直接保存不能被校验拦下） |
| 空 / 纯空白 | nil = 清除 |
| `2026-13` / `abc` / 年份越界（有效区间 1900…2100） | 解析失败 → 保存被拦，
  红字提示留在输入框下方 |

### 展示口径（`CatalogSeries.yearMonthText`）

有月 → `2026-10`；只有年 → `2026`；都没填 → nil（调用方展示 `—`）。
同步更新的展示点：

- 系列管理列表行（`ShopCatalogOpsManageView`）与「编辑」按钮文案；
- 商品详情页主信息卡「店家 · 年月 · 季节 · 类型」行、商品信息 LabeledContent；
- 批次归属详情的系列 Picker（`ShopCatalogBatchDetailView`）；
- 加购备注「年月：2026-10」（`ShopCatalogWardrobeInserter`）。

**年份筛选 chip / 排序不动**：`store.years(inShop:)`、`archiveSeries` 年份过滤、
按年倒序排序继续用 `year: Int?`，语义不变（月份不参与分档）。

## 二、预约价格表：恢复图片上传 + 一次多选

### 数据模型

`CatalogPriceChart` 新增 `var sourceImages: [String]? = nil`（Optional，旧 JSON 缺键
置 nil）：

- `sourceImages` = **完整**多图引用列表（按上传顺序）；
- `sourceImage` 恒等于**首图**——既有的单图展示 / 门禁口径
  （`ShopCatalogChartPresentation.plan`、红线「sourceImage 非空绝不静默 .none」）
  继续以 sourceImage 为唯一入口，不被多图改动牵连。

### 上传入口

`ShopCatalogImagePickerButton` 升级为系统多选（`PhotosPicker` +
`maxSelectionCount: 10`）：

- `.append`：多选按顺序逐张追加成多行「local:文件名」；
- `.replace`（封面等单值字段）：多选只取第一张，旧语义不变；
- 部分保存失败不静默：报「已保存 N/M 张，其余保存失败」。

系列编辑表单「预约价格表」区新增按钮「上传价格表图片（可多选）」；录入文本
（`priceChartImageText`）按行承载引用，落库时经
`CatalogPriceChartImageText.references(fromText:)`（口径唯一，可单测）拆回列表写
`sourceImages`，首图同步写 `sourceImage`。`onAppear` 回填优先 `sourceImages`，
旧数据（只有 sourceImage）按原值回填，保存时归一化为单元素列表。

### 详情页展示

价格表卡展开区：首图仍由 `chartImageBlock(plan.image:)` 渲染（plan 口径不动），
第 2 张起由 `extraPriceChartImages` 补充展示；点任一图进全屏查看器时带上
**全部**原图（含首图），可左右翻阅。

## 三、时光馆加购 → 衣橱图片不显示（根因修复）

### 根因

`ShopCatalogWardrobeDraftBuilder.makeDraft`（`ShopCatalogWardrobeInserter.swift`）
把 `ClothingEditDraft` 的 `imagePaths` **硬编码为 `[]`**。加购落库的 `Clothing`
没有任何图片，而衣橱卡片走 `ImageManager` 文件名体系
（`ClothingCard` → `ImageManager.shared.cachedImage(fileName:)`）——
商品图引用再完整也无处取图，表现为「衣橱不显示图片」。

两套图片体系本来就互不相通：

| 体系 | 存储 | 消费方 |
|---|---|---|
| ShopCatalog | `local:` 引用 / Bundle 画册图（`ShopCatalogImageResolver`） | 商城详情页、系列卡 |
| 衣橱 | `Documents/Images/<文件名>`（`ImageManager`） | `ClothingCard` 等衣橱界面 |

### 修复（复制物化，不是搬移）

新增 `ShopCatalogWardrobeDraftBuilder.materializeImagePaths(for:store:modelContext:)`：

- 引用推导与详情页**同一口径**：`store.asset(id:)?.originalURL ?? 原值`
  （`product.images` 存的是 CatalogAsset id，不是直接引用）；
- `local:` 运营上传图 → Application Support/ShopCatalog/images/ 读出 →
  Bundle 画册图 → 读出 → `ImageManager.shared.saveImage` 落成衣橱图片文件；
- http(s) 远程图不在主线程同步拉网络，跳过（详情页轮播仍可看原图）；
- 上限 6 张；单张失败不阻塞其余；全部失败维持空数组（卡片占位，与旧行为一致）；
- **复制不是搬移**：Catalog 侧引用原样保留，商城展示不受影响。

受益路径：商品详情页加购（现货 / 定金尾款 / 全款 / 心愿）、系列多选套装合并
（主衣物图片随首条记录走）、时光馆珍藏心愿迁移（`TimeHallTreasuredWishMigrator`）。
旧版 `TimeHallWardrobeDraftBuilder`（Legacy 归档页）本来就走
`ImageManager.saveImage`，不在本次改动内。
