# 公告系统测试矩阵

> 更新时间：2026-04-06  
> 用途：为 Notice CMS 提供覆盖产品规则、数据迁移、渠道展示、权限、CloudKit 同步和上线前验证的统一测试矩阵。

## 1. 测试目标

确保公告系统在以下维度上稳定可用：

- 生命周期正确
- 渠道规则正确
- 旧数据迁移正确
- 用户状态流转正确
- 角色权限正确
- CloudKit 环境与同步正确

## 3. T1 生命周期测试

| 编号 | 场景 | 预期结果 |
|---|---|---|
| T1-1 | 新建公告默认保存 | 状态为 `draft` |
| T1-2 | 草稿配置未来时间保存 | 状态为 `scheduled` |
| T1-3 | 草稿立即发布 | 状态为 `published` |
| T1-4 | 定时公告取消定时 | 状态回到 `draft` |
| T1-5 | 已发布公告下线 | 状态变为 `archived` |
| T1-6 | 已归档公告复制 | 生成新 `draft` |
| T1-7 | `endAt` 到期 | 自动进入 `archived` |

---

## 4. T2 用户侧展示测试

| 编号 | 场景 | 预期结果 |
|---|---|---|
| T2-1 | `info` 公告发布 | 仅进入 `inbox` |
| T2-2 | `important` 公告发布 | 可进入 `inbox + banner` |
| T2-3 | `critical` 公告发布 | 可进入 `inbox + modal` |
| T2-4 | 普通公告 | 不触发 `modal` |
| T2-5 | 命中 `modal` 时 | 不同时显示 `banner` |
| T2-6 | 关闭提示后 | 仍可在公告中心查看 |
| T2-7 | 冷启动 30 秒内 | 不弹 `modal` |
| T2-8 | 回前台时 | 先同步，再评估提示 |

## 5. T3 用户状态测试

| 编号 | 场景 | 预期结果 |
|---|---|---|
| T3-1 | 未读公告进入详情 | `unseen -> read` |
| T3-2 | 确认型公告点击确认 | `read -> acknowledged` |
| T3-3 | 关闭 modal 未看详情 | `unseen -> dismissed` |
| T3-4 | `read` 状态公告 | 默认不再弹 `modal` |
| T3-5 | `acknowledged` 状态公告 | 不再显示提示 |
| T3-6 | `dismissed` 状态公告 | 不再弹 `modal`，仍可在 `inbox` 查看 |

## 11. 高风险回归项

- 旧公告升级后全部变未读
- 普通公告错误触发 modal
- `Development / Production` 混淆
- 已归档公告仍出现在用户侧
- `editor` 获得发布权限
- `modal` 与 `banner` 同时出现

## 13. 冻结结论

本测试矩阵冻结以下共识：

1. 公告系统测试不能只测“能不能弹出来”。
2. 生命周期、迁移、权限、环境必须作为同级测试维度。
3. 上线前最少要覆盖用户侧、管理侧、CloudKit、迁移四条主线。
