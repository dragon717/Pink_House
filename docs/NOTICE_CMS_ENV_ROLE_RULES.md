# 公告系统环境与角色规则（A4）

> 更新时间：2026-04-06  
> 对应任务：`NOTICE_CMS_DEV_TASKS.md` 中 A4  
> 用途：冻结公告系统的环境职责与角色权限边界，避免开发环境、生产环境与管理员能力混用。

## 1. 环境规则

### 1.1 `Development`

用途：

- 本地开发
- Xcode 调试
- 样式验证
- 同步流程验证
- CloudKit Schema 开发验证

允许：

- 创建测试公告
- 验证渠道样式
- 验证已读/确认逻辑
- 验证管理员判断与诊断流程

不允许：

- 发布正式运营公告
- 作为真实用户公告来源
- 替代 `Production` 环境做线上内容管理

### 1.2 `Production`

用途：

- TestFlight
- App Store 正式版本
- 正式公告发布
- 正式公告查看与状态流转

允许：

- 创建、发布、下线、归档正式公告
- 真实用户可见的正式投放

要求：

- 所有正式公告必须在此环境完成最终发布

---

## 2. 环境共识

1. `Development` 与 `Production` 数据天然隔离。
2. 调试包看不到生产公告、正式包看不到开发公告，是正常行为。
3. Schema 部署到 `Production` 不等于数据自动复制到 `Production`。
4. 正式运营内容必须在 `Production` 重新创建或发布。

---

## 3. 角色定义

| 角色 | 能力概述 | 典型使用者 |
|---|---|---|
| `reader` | 查看公告、已读、确认 | 普通用户 |
| `editor` | 创建草稿、编辑草稿、预览 | 内容编辑 |
| `publisher` | 发布、定时发布、下线、归档 | 发布负责人 |
| `admin` | 角色配置、环境诊断、审计查看 | 技术管理员/系统管理员 |

---

| 能力 | reader | editor | publisher | admin |
|---|---|---|---|---|
| 查看公告中心 | 是 | 是 | 是 | 是 |
| 标记已读 | 是 | 是 | 是 | 是 |
| 确认公告 | 是 | 是 | 是 | 是 |
| 创建草稿 | 否 | 是 | 是 | 是 |
| 编辑草稿 | 否 | 是 | 是 | 是 |
| 预览公告 | 否 | 是 | 是 | 是 |
| 立即发布 | 否 | 否 | 是 | 是 |
| 定时发布 | 否 | 否 | 是 | 是 |
| 下线公告 | 否 | 否 | 是 | 是 |
| 归档公告 | 否 | 否 | 是 | 是 |
| 回滚公告 | 否 | 否 | 否 | 是 |
| 查看审计日志 | 否 | 否 | 受限 | 是 |
| 管理角色 | 否 | 否 | 否 | 是 |
| 进入诊断页 | 否 | 否 | 受限 | 是 |

---

## 5. 角色行为边界

### 5.1 `editor`

可以：

- 写内容
- 配置渠道
- 配置时间窗
- 预览效果

不可以：

- 正式发布
- 下线线上公告
- 调整角色权限

### 5.2 `publisher`

可以：

- 发布草稿
- 定时发布
- 下线公告
- 归档公告

不可以：

- 修改系统角色配置
- 处理管理员级环境策略

### 5.3 `admin`

可以：

- 查看和管理角色
- 查看审计日志
- 进入环境诊断
- 管理发布流程例外场景

要求：

- 对高风险操作保留完整审计

---

## 6. 入口规则

### 用户侧入口

- 所有用户都可进入公告中心
- 普通用户只看到消费能力，不看到管理能力

### 管理侧入口

- `editor` 看到草稿与预览相关入口
- `publisher` 看到发布相关入口
- `admin` 看到诊断与审计入口

规则：

- 正式发布入口不得挂在“实验室调试工具”之下
- 诊断入口不得承担正式发布职责

---

## 7. 诊断页规则

诊断页可包含：

- 当前环境显示
- 当前角色显示
- CloudKit 同步状态
- 已读状态同步状态
- Schema/权限排查辅助信息

诊断页不可承担：

- 正式线上公告发布
- 越权管理能力
- 代替管理端列表页的长期入口职责

---

## 8. 发布流程规则

正式流程建议：

1. `editor` 创建草稿
2. `editor` 完成预览
3. `publisher` 执行发布或定时发布
4. `publisher` 或 `admin` 负责下线与归档
5. `admin` 负责审计与回滚

---

## 9. 风险控制规则

### 9.1 环境风险

- 不允许把开发环境当成生产发布环境
- 不允许用“调试机器能看到”替代“正式用户能看到”

### 9.2 权限风险

- 不允许继续依赖客户端硬编码管理员 ID 作为长期方案
- 不允许 `editor` 越权发布

### 9.3 运维风险

- 不允许在无审计的情况下直接改线上关键公告
- 不允许把诊断操作当成正式运营操作

---

## 10. 冻结结论

本规则冻结以下共识：

1. 正式公告只在 `Production` 环境发布。
2. 调试环境用于验证，不用于运营。
3. 正式发布入口与诊断入口必须分离。
4. `editor / publisher / admin` 必须职责分层，不能继续只有“管理员/普通用户”两类。
