# 预约价格表解析改造：多模态识别 + 粘贴录入 + 容错（需求 M）

> 2026-09-23 ｜ 涉及「实体管理 → 系列 → 编辑」的预约价格表，以及四处尺码表编辑器
>
> ⚠️ **2026-09-23 后续（需求一）**：本文描述的**「上传价格表图片（自动识别）」入口与失败红字提示
> 已按用户要求整条移除**（用户反馈：识别频繁报错且常驻霸屏）。价格表现在只走
> 「粘贴文本录入（推荐，最准）」+ 手动输入区；`CatalogChartExtraction`（多模态 / OCR / 质量门禁）
> 因此**在 App 内已无调用方**，但按「只删这两处，其他保留」暂未删除。
> 见 `docs/价格表UI精简与系列发售阶段_需求实现说明.md`。
> **本文以下内容是历史实现记录，其中「图片识别」相关的入口说明已不再适用于当前代码。**

## 1. 问题（用户原文摘要）

在「编辑系列 → 预约价格表」上传图片后，自动解析结果**完全不可用**：

1. **只识别出第一列**（款式名），后面的定金 / 尾款 / 预约价 / 现货价全部丢失；
2. **结果没有结构**：出现 `G PROMOTTOI`（英文字母乱码）、`定金:尼款`（错别字）；
3. **乱码被自动填进下方输入框**，用户还得全部删掉重打，"完全失去了自动的意义"。

诉求三条：

1. 接入有表格提取能力的多模态大模型，让它理解**行和列的关系**，直接输出结构化 `标签:值,值`；
2. 增加**「直接粘贴」入口**，整段文本贴进来就能按行拆分保存；
3. **容错**：识别失败不要填乱码，弹窗提示「解析失败，请手动录入」并保持输入框为空。

用户最后一句是判据：**"我需要的是能直接复制粘贴的规整文本，不是一堆连列都没对齐的乱码。"**

## 2. 根因

| 现象 | 根因 |
|---|---|
| 只识别第一列 | 只走 Vision OCR + 包围盒行重建。对**设计过的**图表（彩色底、艺术字、大列距），小字号数字容易整列漏识别；而"解析成功"的定义太弱——只要凑出行列就算成功 |
| `G PROMOTTOI` 乱码 | OCR 把装饰性英文当成表头，没有任何乱码判定 |
| `定金:尼款` 错位 | 行标签与列名重名（行列错位）没有任何校验 |
| 乱码填进输入框 | `parsePriceChart` 在"成功"分支无条件覆盖 `priceChartColumnsText / priceChartRowsText`，垃圾也被当成成功结果写进去 |
| 只能手敲 | 除图片识别外没有任何导入通道 |

一句话：**没有质量门禁，也没有第二条录入路径。**

## 3. 方案：三层提取 + 一条并列主入口

```
上传图片
   │
   ├─ ① 多模态大模型（Qwen-VL，App 内既有通道）
   │     提示词要求「列名行 + 行标签:值,值」，禁止 Markdown / 解释 / 猜测
   │        │
   │        └─ 过门禁？ ── 是 ──▶ 写入输入框（提示核对）
   │                          └─ 否 ─┐
   ├─ ② 端上 Vision OCR（既有 CatalogChartParser）│
   │        └─ 过门禁？ ── 是 ──▶ 写入输入框    │
   │                    └─ 否 ─┐               │
   └───────────────────────────┴───────────────┘
                                ▼
                   ③ 弹窗「解析失败，请手动录入」
                      输入框恢复识别前内容（一个字都不写）
                      ▼
              并列主入口：「粘贴文本录入」
```

### 3.2 质量门禁（`CatalogChartQuality`）

任何来源的结果都必须过门禁，命中任一条即**判定解析失败**：

| 检查 | 拦截的现象 |
|---|---|
| 列数 < 2 | 「只识别出第一列」的极端形态 |
| 无数据行 | 只有表头 |
| 数据格填写率 < 0.4 | 「列名在、每行只有款式名」——覆盖度不足 |
| 全表无数字 | 价格表 / 尺码表的数据格必然带数字 |
| 乱码词元 | `PROMOTTOI` 型：连续 ≥3 个大写拉丁字母；或拉丁字母 ≥3 且无元音。白名单放过 `Size / Bust / CM / XS` 等正常英文表头 |
| 行标签与列名重名 | `定金:尼款` 型行列错位 |
| 混入说明文字 | 行标签是「列名 / 备注 / 说明 / 注意…」 |

乱码判定刻意保守（先放过 `S / M / L / XL`，再走白名单），避免误杀正常尺码表。

### 3.3 多模态提示词要点

- 明确"第一行 = 列名，其余 = `行标签:值,值`，值的个数必须与列数一致"；
- 明确"图片里没有内容的格子留空（两个相邻逗号）"；
- 明确"不要解释、不要 Markdown、不要代码块"；
- 明确"看不清一律留空，**绝对不要猜测、不要编造**"；
- 明确"标题 / 店铺名 / 备注 / 水印一律忽略"。

模型回复在进入解析前会清洗：去代码围栏、`**粗体**`、行首列表符号、`列名:` 前缀，
并丢弃叙述句（有冒号但冒号后既无分隔符也无数字 = 前言 / 备注）。

### 3.4 「粘贴文本录入」（并列主入口）

一个面板解决，整段丢进来即可：

- **三种来源都认**：
  1. 「列名行 + 每行 `标签:值,值`」（推荐格式）；
  2. Markdown 表格（`| 款式 | 预约价 |`，自动跳过 `|---|` 分隔行）；
  3. 从 Excel / Numbers 直接复制（制表符分隔）。
- **无需严格对齐**：列名行写成 `款式,预约价,定金,尾款`，数据行写成
  `大蝴蝶结背心裙,318,91,227`（无冒号）也能识别——首段当标签、其余当值。
  这正是用户要的"能直接复制粘贴的规整文本"。
- **自动忽略非表格文字**：表标题、店铺名、尾注（无分隔符的行直接丢弃）。
- **全角标点归一**：`：` `，` `｜` 全角空格都当分隔符（中文输入法友好）。
- **列名行自动剔行标签列**：`款式 / 尺码 / 项目` 这类列名会被剔除，避免详情页出现重复列 + 整体错位。
- **实时预览 + 预览即落库**：预览用的是保存链路同一套解析
  （`parseColumns → parseRows → normalized`），所见即所存。
- **剪贴板一键填入** + 打开时检测剪贴板是否有内容并提示。

### 3.5 容错（需求第 3 条的执行点）

```swift
let snapshot = (columns: priceChartColumnsText, rows: priceChartRowsText)   // 识别前快照
do {
    let outcome = try await CatalogChartExtraction.extract(image: image, kind: .price)
    // 只有过了门禁才会走到这里
    priceChartColumnsText = outcome.table.columns.joined(separator: ",")
    ...
} catch {
    // 恢复快照：识别结果一个字符都不写入
    failPriceChartParse(error.localizedDescription, restore: snapshot)
}
```

失败时：

1. 输入框恢复成识别前的内容（原本是空的就还是空的）；
2. 页面常驻一行红字「上次识别失败，未写入任何内容：<原因>」；
3. 弹窗标题「**解析失败，请手动录入**」，正文给出具体原因 + "原图已保留"，
   按钮「粘贴文本录入」/「知道了」；
4. 原图引用始终保留（详情页可查看原图）。

## 4. 验收口径

- **编译**：`xcodebuild -target ItemManager`（主 target）通过；
- **单测**：`ItemManagerTests/CatalogChartExtractionTests` 覆盖
  - 三类用户实测垃圾（只识别第一列 / `G PROMOTTOI` / `定金:尼款`）**必须被判为不可用**；
  - 多模态回复解析（纯文本 / 围栏 / Markdown / 尺码表）；
  - 整段粘贴解析（列名行 + 无冒号数据行 / 无列名行 / 制表符 / Markdown / 全角标点 / 标题尾注 / 缺格）；
  - 预览即落库（回填文本再走保存链路，列与行必须一致）。
- **UI**：系列编辑页 → 预约价格表 → 上传图片失败时弹窗且输入框为空；
  「粘贴文本录入」→ 贴入整段文本 → 预览 → 识别并填入 → 保存。

## 5. 未做 / 后续

- 端上 OCR（Vision）本身的识别率没有提升，只是**被门禁兜住了**：
  它现在只在多模态不可用时作为兜底，且结果不合格就不采用。
- 多模态通道依赖 `AIConfigManager.shared.qwenApiKey`
  （设置 → 智能管理 → `QWEN_API_KEY`，标注"用于 Qwen3-VL 视觉识别"）。
  未配置时图片识别只剩端上 OCR，粘贴入口不受影响。
- 图片识别是**可选**能力：识别失败不影响录入，粘贴与手填始终可用。
