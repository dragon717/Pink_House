# 公告系统发布 / 下线 / 回滚 SOP（H3）

> 更新时间：2026-04-07  
> 用途：定义公告系统正式运营流程，供编辑、发布负责人和管理员执行，避免将调试流程误用为正式发布流程。

## 1. 适用范围

适用于 Notice CMS 在 `Production` 环境中的正式操作：

- 发布
- 定时发布
- 下线
- 归档
- 回滚

不适用于：

- `Development` 调试验证
- 临时代码测试

---

## 2. 角色分工

| 角色 | 责任 |
|---|---|
| `editor` | 创建草稿、编辑内容、预览 |
| `publisher` | 发布、定时发布、下线、归档 |
| `admin` | 回滚、审计、环境诊断 |

---

## 3. 发布 SOP

### 3.1 创建草稿

责任人：

- `editor`

步骤：

1. 新建草稿
2. 填写标题、摘要、正文
3. 配置媒体
4. 配置动作
5. 保存草稿

检查项：

- 标题非空
- 正文非空
- 媒体资源有效

### 3.2 配置投放

责任人：

- `editor`

步骤：

1. 选择 `channel`
2. 选择 `severity`
3. 设置 `publishAt/startAt/endAt`
4. 配置 `audience`
5. 配置 `requiresAck`
6. 配置版本范围

检查项：

- `modal` 仅用于 `critical`
- 时间窗合法
- 版本范围合法

### 3.3 预览

责任人：

- `editor`

步骤：

1. 预览 `inbox`
2. 预览 `banner`
3. 预览 `modal`
4. 检查长文、媒体、按钮、确认态

检查项：

- 列表摘要可读
- 详情内容无明显排版错误
- banner/modal 不截断关键内容

### 3.4 发布前核对

责任人：

- `publisher`

步骤：

1. 确认当前环境为 `Production`
2. 确认角色权限正确
3. 确认公告状态为 `draft` 或 `scheduled`
4. 确认发布时间设置正确

禁止：

- 在 `Development` 环境执行正式发布
- 未预览直接发布

### 3.5 立即发布

责任人：

- `publisher`

步骤：

1. 点击发布
2. 记录发布动作
3. 检查发布结果
4. 在用户侧入口做抽样验证

验证项：

- 公告中心可见
- banner/modal 行为符合预期
- 审计记录写入成功

### 3.6 定时发布

责任人：

- `publisher`

步骤：

1. 设置定时时间
2. 保存为 `scheduled`
3. 发布前再次核对时间窗
4. 到点后验证自动进入 `published`

验证项：

- 自动发布时间准确
- 到点后列表/渠道查询正确

---

## 4. 下线与归档 SOP

### 4.1 下线

责任人：

- `publisher`

适用场景：

- 内容不再适合对用户展示
- 临时投放需要结束

步骤：

1. 进入已发布公告
2. 执行下线
3. 确认公告退出用户可见面
4. 写入操作日志

### 4.2 归档

责任人：

- `publisher`

适用场景：

- 公告自然过期
- 已下线公告需保留历史

步骤：

1. 将状态切换为 `archived`
2. 写入 `archivedAt`
3. 确认管理端历史可见

---

## 5. 回滚 SOP

### 5.1 适用场景

- 发布错误内容
- 时间窗配置错误
- 渠道配置错误
- 线上展示异常

### 5.2 操作角色

- `admin`

### 5.3 操作步骤

1. 进入发布历史
2. 选择目标历史版本
3. 确认回滚原因
4. 执行回滚或复制为新草稿
5. 验证当前线上版本

说明：

- 优先“复制为新草稿再发布”
- 不建议无记录地直接覆盖线上内容

---

## 6. 发布后核查 SOP

发布时间后必须检查：

1. 公告中心可见性
2. 详情页打开正常
3. 渠道命中是否正确
4. 用户状态写入是否正常
5. 审计记录是否存在

建议抽样验证：

- 普通用户视角
- 管理员视角
- 不同系统状态或账号视角

---

## 7. 故障处理 SOP

说明：

- 当前阶段如遇到 `modal` 相关问题，优先配合 `NOTICE_CMS_MODAL_DEBUG_CHECKLIST.md` 使用。
- 本节负责给出故障入口，专项清单负责给出更细的执行步骤。

### 7.1 发布后看不到公告

按以下顺序排查：

1. 当前是否在 `Production`
2. 公告是否为 `published`
3. 时间窗是否命中
4. 版本范围是否命中
5. Query/索引是否正常
6. 当前是否只是本地缓存可见，而非本次云同步成功

若日志出现：

- `拉取公告 失败: 参数无效`

优先转入专项清单中的 CloudKit 查询与索引排查。

### 7.2 公告重复提示

按以下顺序排查：

1. 用户状态是否正确写入
2. `presentationCount` 是否正确更新
3. `modal` 节流规则是否生效

### 7.3 不该弹 modal 却弹了

按以下顺序排查：

1. `severity`
2. `channel`
3. 用户状态
4. 冷启动/回前台窗口规则

### 7.4 杀端重启后仍不弹

按以下顺序排查：

1. CloudKit 公告是否拉取成功
2. 公告是否满足 `critical + modal`
3. 是否仍在冷启动 30 秒窗口内
4. 用户状态是否已进入 `read / dismissed / acknowledged`

### 7.5 已看到管理页公告，但用户侧不弹

按以下顺序排查：

1. 先区分公告来源是“本地已有”还是“本次云同步”
2. 再核对该公告是否进入 modal 候选
3. 最后核对用户状态与节流规则

---

## 8. 禁止项

以下行为禁止：

1. 用诊断页直接作为正式发布入口
2. 用开发环境发布正式公告
3. 跳过预览直接上线
4. 不记审计直接修改线上关键公告

---

## 9. 上线前最终检查清单

- [ ] 当前环境确认是 `Production`
- [ ] 公告字段配置完整
- [ ] 时间窗合法
- [ ] 渠道合法
- [ ] 已完成预览
- [ ] 审计能力正常
- [ ] 用户侧抽样验证正常

---

## 10. 冻结结论

本 SOP 冻结以下共识：

1. 公告正式发布是运维流程，不是调试操作。
2. 角色分工必须体现到实际操作步骤中。
3. 回滚优先走有记录、可追踪的方式。
