## 1. 目标与范围

本协议定义“萌宠对话”的统一渲染容器，保证：
- 单轮单气泡（Single Bubble）
- 气泡内完成大多数交互（聊天内闭环优先）
- 多信息并列展示，不再连续弹出多个气泡

> 说明：本协议不定义意图识别细节，意图层见映射文档。

## 2. 单气泡结构（逻辑分区）

每轮回复仅返回一个 `bubble`，内部可包含以下分区：
- `mainText`：主回复文案（必填）
- `infoPanels[]`：并列信息卡（如天气、穿搭、货币）
- `statusPanel`：状态卡（4+1，按需展开）
- `interactiveModule`：内嵌交互模块（背包/商店/领养/数钱/切换）
- `guideOptions[]`：A/B/C 引导选项（多意图冲突时启用）
- `navPrompt`：跳转确认模块（非白名单跳转时启用）

### 2.1 推荐数据模型（示意）

```json
{
  "bubble": {
    "mainText": "……",
    "infoPanels": [],
    "statusPanel": null,
    "interactiveModule": null,
    "guideOptions": [],
    "navPrompt": null
  }
}
```

## 3. 响应式布局规范

- 手机竖屏：`infoPanels` 2 列以内，超出折叠为“查看更多”。
- 窄屏（小屏设备）：降级为纵向卡片堆叠，不拆分新气泡。
- 横屏/Pad：允许 2~3 列，但必须保持同一气泡容器边界。
- 任意尺寸下，`guideOptions` 固定放在气泡尾部，避免漂浮到第二气泡。

## 4. 关键业务展示规则

### 4.1 天气 + 穿搭
- 同轮命中天气与穿搭时，合并到同一个 `bubble.infoPanels[]`。
- 不允许“天气一泡 + 穿搭一泡”的连续弹泡。

### 4.2 状态 4+1
- 基础状态：饱食、饮水、清洁、心情。
- 新增状态：亲密度，使用 **桃心 icon 进度条**。
- 默认展示摘要；用户明确查询状态时展示完整面板。

### 4.3 货币面板
- 对话内展示喵币、鱼币、骨头币余额。
- 不强制跳转资产页面。

### 4.4 领养与多宠
- 首次进入：展示领养容器（左右滑动选奶茶/毛毛）。
- 二胎：在容器中展示“60喵币领养”确认与反馈。
- 切换：在容器中完成宠物管家切换。

### 4.5 背包/商店/数钱
- 背包与商店优先内嵌容器实现可交互操作。
- 数钱容器内嵌，金额直接绑定裙装总价值。

### 4.6 即时投喂动效（`Instant Feed`）
- 名称落地：**即时投喂（Instant Feed）**。
- 触发入口：
  - 用户在萌宠对话中明确发出投喂语义（如“喂，你吃小鱼干”）。
  - 用户在聊天内背包/商店模块点击食物或饮水商品。
- 行为约束：
  - 命中食物/饮水时，执行“购买（如需要）+ 立即投喂”一体化流程。
  - 当前版本用 emoji 动效承载反馈，不新增第二个气泡。
- 透明视频资源预留：
  - 资源命名：`pet_feed_<itemId>_alpha.mov`
  - 约定：支持 Alpha 通道（透明视频），可按道具逐步补齐资产。
  - 无视频资产时自动回退为 emoji 动效。

## 5. 跳转守门协议

- 白名单（如裙装详情）可直跳。
- 非白名单必须在 `navPrompt` 里先询问用户确认。
- 用户拒绝跳转后，优先提供聊天内替代操作。

## 6. 失败与降级策略

- 复杂模块渲染失败时，保持单气泡，回退为文本 + 简化操作按钮。
- 禁止因模块失败而拆分第二个气泡补发内容。

## 7. 观测指标（协议侧）

- 单轮多气泡率
- 单气泡渲染成功率
- 模块降级率
- 跳转确认触发率
