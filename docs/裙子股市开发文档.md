# 裙装股市 - 开发文档

> 一个基于 SwiftData + CloudKit Public DB + AI 的分布式 Lolita 裙装监控系统

---

## 一、项目概述

### 1.1 核心理念

**裙装股市** 是一个将金融股市概念与 Lolita 文化相结合的分布式监控平台。它利用多台 iPhone 作为计算节点，实时追踪闲鱼、小红书、淘宝、微店等平台的 Lolita 裙装价格变动，通过 AI 去重和情感分析，为用户提供"股市级"的购物决策支持。

### 1.2 情感枢纽

项目的情感价值在于：

- **为爱发电**：Lolita 裙装价格昂贵且市场信息不对称，帮助同好找到好价
- **极客浪漫**：用分布式计算和 AI 技术解决日常购物痛点
- **社群归属**：每台 iPhone 都是一个节点，用户既是使用者也是贡献者
- **审美坚持**：莫妮卡粉主题色体现 Lolita 文化的精致美学

### 1.3 命名由来

- **裙装**：直指核心商品 - Lolita 裙装和小物
- **股市**：借鉴金融市场的数据可视化方式，将商品价格波动类比股票价格
- **LO-指数**：Lolita Index，综合反映市场热度的核心指标

## 三、核心模块详解

### 3.1 数据模型

#### 3.1.1 LolitaItem - 商品实体
```swift
@Model
final class LolitaItem {
    @Attribute(.unique) var platformID: String  // 平台+ID唯一标识
    var platform: PlatformType                  // 来源平台
    var rawTitle: String                        // 原始标题
    var cleanedName: String?                    // AI清洗后名称
    var currentPrice: Double                    // 当前价格
    var semanticHash: String?                   // 语义哈希（用于去重）
    var isDeleted: Bool                         // 软删除标记
    // ... 其他属性
}
```

**设计要点**：
- 所有非可选属性都有默认值，满足 CloudKit 要求
- `platformID` 使用 `@Attribute(.unique)` 实现基础去重
- `semanticHash` 用于 AI 语义去重

#### 3.1.2 SkirtStockMetric - 股市指标
```swift
@Model
final class SkirtStockMetric {
    @Attribute(.unique) var metricID: String    // 裙装名+时间戳
    var skirtName: String                       // 萌款名称
    var timestamp: Date                         // 统计时间
    var highPrice: Double                       // 最高价（K线）
    var lowPrice: Double                        // 最低价（K线）
    var averagePrice: Double                    // 平均价
    var listingCount: Int                       // 挂牌数量
    var sentimentScore: Double                  // 情绪指数
    // ... 平台分布、AI指标等
}
```

**设计要点**：
- 按小时统计，支持 K 线图绘制
- 包含情绪指标（由 MiniMax 分析得出）
- 记录平台分布（闲鱼/小红书/淘宝/微店）

#### 3.1.3 LolitaMarketIndex - 大盘指数
```swift
@Model
final class LolitaMarketIndex {
    @Attribute(.unique) var timestamp: Date
    var indexValue: Double      // LO-指数值（基准1000）
    var changePercent: Double   // 涨跌幅
    var totalListings: Int      // 总挂牌量
    var activeNodes: Int        // 活跃节点数
}
```

### 3.2 分布式任务调度

#### 3.2.1 TaskDispatcher - 任务分发器

**核心功能**：
1. **节点注册**：每台设备启动时注册为计算节点
2. **任务领取**：抢占式领取未处理的任务
3. **心跳机制**：定期更新节点状态
4. **故障转移**：节点离线时任务重新分配

**任务类型**：
- `search`：关键词搜索任务
- `detail`：商品详情抓取
- `user`：用户商品列表抓取

#### 3.2.2 任务生命周期

```
创建任务 → 待分配 → 已分配 → 处理中 → 完成/失败
   ↑___________________________________________|
```

### 3.3 AI 去重服务

#### 3.3.1 双层去重架构

```
第一层：基础去重（SwiftData @Attribute(.unique)）
    ↓
第二层：内存索引去重（SkirtIndexCache）
    ↓
第三层：AI 语义去重（MiniMax + Qwen-3-VL）
```

#### 3.3.2 SkirtIndexCache - 内存索引缓存

**设计目的**：
- Public DB 不会自动去重，需要在写入前检查
- 将索引加载到内存，实现 O(1) 去重查询

**索引结构**：
```swift
class SkirtIndexCache {
    private var semanticHashIndex: [String: [SkirtIndexEntry]]  // 语义哈希索引
    private var platformIDIndex: [String: SkirtIndexEntry]      // 平台ID索引
    private var brandIndex: [String: [SkirtIndexEntry]]         // 品牌索引
}
```

#### 3.3.3 AI 去重流程

1. **文本分析（MiniMax）**：
   - 提取品牌、裙名、颜色、型号、价格、成色
   - 生成 `semanticHash`（如：`Baby-铭记-JSK-白色`）

2. **内存索引检查**：
   - 检查 `semanticHash` 是否已存在
   - 存在则更新价格，不存在则进入下一步

3. **视觉验证（Qwen-3-VL）**：
   - 分析商品图片特征
   - 验证是否与已有商品为同一实物

4. **决策**：
   - 重复商品：保留最低价或标记"疑似同一商品"
   - 新商品：写入 Public DB

### 3.4 隐私保护的节点显示

#### 3.4.1 NodeCountFormatter

**设计原则**：保护真实节点数量，防止竞争对手分析

| 真实数量 | Debug显示 | 发行版显示 |
|---------|----------|-----------|
| 0-99 | 真实值 | 真实值 |
| 100-999 | 真实值 | 模糊值（如"120+"） |
| 1000+ | 真实值 | "999+" |

**时间因子**：应用运行时间越长，模糊值越接近真实值（30分钟达到真实值）

## 六、技术难点与解决方案

### 6.1 CloudKit 集成问题

**问题**：`CloudKit integration requires that all attributes be optional, or have a default value set`

**解决**：为所有非可选属性添加默认值
```swift
var platformID: String = ""
var currentPrice: Double = 0.0
var isDeleted: Bool = false
```

### 6.2 跨 ModelContainer 查询

**问题**：裙装股市使用独立的 `publicContainer`，但 SwiftUI `@Query` 默认使用 `SharedPersistence`

**解决**：手动从 `SkirtMarketPersistence.shared.mainContext` 获取数据
```swift
private func loadData() async {
    guard let context = SkirtMarketPersistence.shared.mainContext else { return }
    let descriptor = FetchDescriptor<LolitaMarketIndex>()
    marketIndices = (try? context.fetch(descriptor)) ?? []
}
```

### 6.3 后台任务限制

**问题**：iOS 对后台网络请求限制严格

**解决**：
- 使用 `BGAppRefreshTask` 申请后台执行时间
- 通过静默推送唤醒设备
- 分布式设计降低单设备压力

### 6.4 反爬对抗

**问题**：闲鱼、小红书等平台有严格的反爬机制

**解决**：
- 利用 iOS 快捷指令的真实浏览器环境
- 分布式 IP 降低单点风险
- 模拟人类行为的随机轮询
