# VIP UI 设计思路与最佳实践

更新时间：2026-04-03

## 1. 这次 UI 的核心思路

这次 VIP 页不是单纯把截图“抄出来”，而是先拆成可复用的视觉语言，再把现有业务功能重新映射进去。

核心做法有三层：

- 先定同源主题
  - 黑色背景 + 亮黑玻璃卡
  - 深蓝背景 + 冰蓝玻璃卡
  - 莫妮卡粉背景 + 亮粉玻璃卡
- 再定卡片层级
  - 页面背景负责情绪氛围
  - Hero 卡负责身份感和主要价值
  - 权益卡负责信息分组
  - 底部购买面板负责行动收口
- 最后才映射功能
  - 不为了放功能而放功能
  - 每个权益都必须能落回现有能力或未来明确预留位

## 2. 适合这类 VIP 页的 UI 方法

### 2.1 先做视觉 token，不要先堆组件

这次先抽出了：

- `VIPVisualTheme`
- `VIPGlassStyle`
- `VIPGlassCardBackground`

这样做的好处：

- 背景色、描边、柔光、卡面高光不会散落在每个 view 里
- 试用弹窗、权益卡、底部购买条能保持同源
- 后面再加主题时，不会变成复制粘贴式改 UI

经验：

- 一个主题至少要同时定义
  - 背景渐变
  - 主玻璃卡
  - 次级玻璃卡
  - 强调色
  - 次级文字色
  - 柔光色

### 2.2 玻璃感不要只靠 `.ultraThinMaterial`

如果只上系统毛玻璃，很容易变成“淡灰一层”。

更稳的做法是四层叠加：

1. 深色或彩色渐变底
2. material 做基础透感
3. 顶部高光渐变
4. 柔光描边和外发光

这次 `VIPGlassCardBackground` 就是按这个思路做的。

### 2.3 复杂权益页要先做信息架构

VIP 页最容易失败的地方不是样式，而是信息层级。

这次按“情绪 -> 权益 -> 套餐 -> 行动”收拢：

1. 顶部品牌栏
2. Hero 身份卡
3. 权益宫格
4. 套餐选择
5. 主 CTA
6. 协议和说明

原则：

- 屏幕第一眼先看到“为什么值得开”
- 第二眼看到“具体能得到什么”
- 第三眼才是“怎么买”

### 2.4 VIP 引导要拦能力，不要拦入口

这是这轮最重要的交互原则之一。

不要做成：

- 用户一进页面就被拦
- 用户一进入口就弹权限墙

更推荐：

- 入口保留
- 本地能力继续可用
- 只有触发第三方模型/API 时才升级引导

这样体验更顺，也更符合“先让用户感受到陪伴，再引导升级”的语气。

### 2.5 “专属感”来自可切换，而不只是说明文案

纯文案型 VIP 权益很虚。

更能成立的专属感是：

- 身份编号
- 卡片皮肤
- 应用图标
- 以后可继续扩的主题皮肤

所以这次把 `个性图标` 从文案占位推进成了真实可切换能力。

## 3. 这次 UI 相关的最佳实践

### 3.1 一个页面只保留一个主情绪

这次整体坚持“深色、高光、收藏感、尊贵感”。

不要在同一个 VIP 页里混：

- 奶白卡片
- 荧光色按钮
- 多套不相关插画
- 过多高饱和标签

否则会失去“会员页”的稳定气场。

### 3.2 一个页面只保留一个强动作区

底部购买条是唯一主动作区。

这样做的好处：

- 套餐选择和 CTA 永远在同一视觉收口区
- 顶部和中部都可以安心做叙事，不会抢按钮

### 3.3 复刻截图时，不要复刻无意义噪音

应该复刻的是：

- 色温
- 卡片厚薄关系
- 柔光描边
- 信息密度
- 标题与副标题节奏

不应该机械复刻的是：

- 没有业务含义的装饰块
- 纯截图式占位图
- 与现有功能完全脱节的入口

### 3.4 先把可持续扩展位留好

这次在 UI 和模型层都留了扩展位：

- `VIPPlan`
- `VIPBenefit`
- `VIPVisualTheme`
- `VIPAppIconOption`

这意味着后续再加：

- 新套餐
- 新会员权益
- 新卡面
- 新图标库

都不用推翻现有结构。

### 3.5 折扣标识要抽成共享组件

像 `-5% OFF`、`-40% OFF`、`-10% OFF` 这种内容不会只出现一次。

所以不要把它当成某一页的临时小装饰，而要当成跨页面复用的视觉组件。

## 4. 应用图标切换的产品与实现思路

### 4.1 调研结论

`8b9cf4d` 这次提交做了三件事：

- 移除了旧的 `AppIcon.appiconset`
- 引入了 `少女心愿logo.icon`
- 将应用主图标切到“少女心愿立体 logo”方案

当前很适合把它沉淀为 VIP 图标库的一项真实权益。

### 4.2 为什么图标切换要纳入 VIP UI 体系

图标不只是设置项，它其实是桌面层的身份延伸。

所以它更适合放在：

- VIP 中心
- VIP 身份体系
- 个性收藏权益

而不是随便塞进普通设置页里。

### 4.3 这次的落地方式

实现拆成四层：

1. 图标资源
   - `少女心愿logo.appiconset`
   - `VIPIconPinkWish.appiconset`
   - `VIPIconDreamCloset.appiconset`
   - `VIPIconPearlWardrobe.appiconset`
   - `VIPIconMoonWardrobe.appiconset`
2. 图标切换服务
   - `VIPAppIconManager`
3. VIP 图标选择页
   - `VIPAppIconSelectionView`
4. VIP 中心入口
   - `VIPCenterView`

这样后续加图标时，只要：

- 新增一个 icon asset
- 在 `VIPAppIconManager.availableIcons` 增一项
- 在 `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES` 注册 alternate icon 名称

就能继续扩。

## 5. 以后继续做这类 UI 时的执行清单

先做这些，再开写 SwiftUI：

1. 先写清楚页面情绪关键词。
2. 先列出主题 token，而不是先画组件。
3. 先画信息层级，再填业务入口。
4. 只保留一个主动作区。
5. 把未来要扩的权益抽成模型。
6. 权益说明必须能映射到真实功能或明确预留接口。
7. 对 VIP 能力做“入口开放，远程能力升级引导”的统一口径。

## 6. 对这次改造的结论

这次最值得保留的不是某个按钮或某种渐变，而是这套方法：

- 先抽视觉系统
- 再映射业务权益
- 再统一入口与权限分层
- 最后把“身份感”做成真实可切换能力

这个方法后面也可以直接复用到：

- 主题皮肤商店
- 会员周报
- 个性化收藏页
- 高级设置页
