# 阶段审查清单

> **使用时机**：每完成一个阶段任务，在 `git commit` **之前**。
> **使用方式**：派子代理（subagent）按本文件逐项审查，四项全通过才允许提交。
> **出处**：`Agent.md` 第 3 章（阶段审查）与第 4 章（Git 与提交规范）。

---

## 〇、派发子代理的 prompt 模板

> 子代理看不到当前对话，prompt 必须自包含。复制下面这段并填好括号内容。

```text
你是本阶段的审查员。仓库绝对路径：<仓库绝对路径>。

【本阶段做了什么】
<一句话目的>
文件清单：
- path/to/A.swift（新增/修改，做了什么）
- path/to/B.swift（新增/修改，做了什么）

【原需求】
<需求原文，或需求文档的相对路径>

每项给出「通过 / 不通过」，不通过必须给出：文件:行号 + 问题描述 + 建议修法。

【输出格式】
## R1 代码是否满足需求

（不通过时列问题清单）

...

## 总结
是否允许提交：是 / 否
必改项：<编号列表>
建议项：<编号列表>
```

## R4 — git 环境是否正确

| # | 检查点 | 判定标准 | 常见不通过 |
| :-- | :-- | :-- | :-- |
| R4.1 | 分支正确 | 在预期分支上（功能分支 / `main`），不是误留在别的分支 | 在 `main` 上直接改大功能 |
| R4.2 | 无误提交文件 | 无 `.env`、密钥、大文件、构建产物、`temp/` | `.env` 进了暂存区 |
| R4.3 | 暂存范围精确 | 只含本阶段文件，无无关改动（重构/格式化/他人改动） | `git add .` 带进一堆 |
| R4.4 | 无遗留临时文件 | 无 `.backup`、`.bak`、日志、截图未清理 | `log.txt` 混进去 |
| R4.5 | 工作区状态清晰 | 未跟踪文件已确认归属（该加的加、该忽略的忽略） | 一堆 `??` 没处理 |
| R4.6 | 提交信息合规 | 中文、`<type>: <一句话>`、言简意赅 | "update files"、"修改了一些代码" |
| R4.7 | 无危险操作 | 未 force push、未 `--no-verify`、未强改历史 | 强推覆盖远程 |
| R4.8 | 远端同步 | 明确本阶段是否需要 push；需要时确认分支有对应远端 | 推到了错误分支 |

**R4 快速核查命令**：

```bash
git branch --show-current        # R4.1
git status --short               # R4.2 / R4.3 / R4.4 / R4.5
git diff --cached --name-only    # R4.3
git check-ignore -v <可疑文件>    # R4.2
git log --oneline -5             # R4.6 风格一致性
```

## 判定与处置

| 审查结论 | 动作 |
| :-- | :-- |
| R1~R4 全通过 | 允许提交，进入 `Agent.md` 第 4 章 |
| 有「不通过」 | 修复 → **重新派审**（只复审失败项及其受影响项） |
| 有「建议项」 | 不阻断提交，但记录进 `MEMORY.md` 技术债台账 |
| 有争议 | 登记进 `MEMORY.md` 第七节「待裁决」，向用户说明，按用户裁决执行 |

**禁止**：审查不通过仍提交；把审查结论跳过直接 commit。

## 提交动作（审查通过后）

```bash
git add <明确的文件路径>        # 禁止 git add -A / git add .
git commit -m "feat: 中文一句话说清楚做了什么"
```

type 取值：`feat` / `fix` / `refactor` / `perf` / `docs` / `test` / `chore`。

一句话标准：**说清"做了什么"，不写过程、不写文件清单**。

| 好 | 坏 |
| :-- | :-- |
| `fix: 修复衣橱统计把定金重复计入总价的问题` | `fix: 修改 Clothing.swift 和 WardrobeView.swift` |
| `feat: 心愿尾款新增按月汇总视图` | `feat: 完成尾款模块开发，改了很多文件` |
| `refactor: 拆分 PetChatView 的消息气泡组件` | `refactor: 重构` |
