## 5. 贯穿全局的规则

**R1 · 拉取后安全合并（2026-10-11 取代旧删除式对齐）**
运营点击「同步更新并上传」，系统拉取并校验最新远端，以同环境基线三方合并。
本机独有新增保留，同字段冲突由用户选择；远端没有某实体不能视为删除。
iOS 覆盖层仅保存相对远端的新增和修改，远端基线版本与正文原子落盘。
旧对齐 UI、删除式对齐函数、独立暂存入口及无调用报告/采用接口已删除。
详细证据见 [安全同步与恢复记录](SHOP_CATALOG_SYNC_RECOVERY_2026-10-11.md)。

**R2 · 软删除 = 墓碑，云端只标记不物理删除**
只有「本地显式删除 + 该删除信息已同步到云端」，云端才标记删除。
表达：`ShopCatalogChangeSet.tombstoneIDs`（语义是**下架**，不是漏传）；
三方合并中墓碑取**并集**，本地独有墓碑留在覆盖层 → 防止已删条目本地复活。
✅ **已验证（原 A14 / C8 的未验证项）**：Mac 发布时墓碑确实随包写进云端 ——
A10 发布后线上 `removedProductIDs=['product-cd812fba']`，A12 拉回仍看得到；
且 **seq 3 那个包在线上依然存在**（`pack_exists=True`）→ 发布头切了、内容没被物理删。

**R3 · 同机模拟怎么做才算数**
- Mac 端：开**第二个草稿容器**当作「另一台机器」。
- iOS 端：**清缓存 / 重装**，让本地沙盒里没有这些图 —— 这才是有效的验证，
  否则 `local:` 引用在本机能解析，看起来像成功，其实没走远端。

**R4 · 发布入口自动先拉取、合并、校验基线**
公共协议仍采用不可变整包快照，上传前将本机新增与修改叠加到最新远端；
没有变化直接完成同步。原图按内容摘要去重，目录包构建后再次核对基线，
再使用 changeTag 条件切换发布头。无法读取或线上已变化时停止，保留本机内容。
冲突选择只对当时的本机内容与远端摘要有效，任一侧变化必须重新核对。

**R5 · 已有公共媒体需要真实远端存在性证明（2026-10-09 已闭环）**
拉回的 `thmedia:<摘要>` 引用通过只读路径确认已有资源，已存在且一致时跳过上传；
新增图片按内容摘要上传并回读校验。原图缺失或远端校验失败均在切换发布头前停止。
2026-10-07 的误报缺图阻塞为历史问题，不改变 R4 的先拉取、合并、条件发布流程。

**R6 · 演练也会播报 `switchHead` / `confirmHead`（文案缺口，暂不影响判定）**
`run_child` 是按**子进程打印的步骤标记**翻译阶段的，与 `dryRun` 无关，而
`publish_cloudkit.py --dry-run` 照样把七步名字都打出来 → 演练日志里会出现
「切换发布头」字样（`reachedHeadSwitch` 在演练中为 `true`）。
**为什么现在不判它失败**：`OpsBridgeRunResult.reachedHeadSwitch` 全仓**只有声明、
没有任何消费方**（死代码），App 侧「记一次已发布」受
`dryRun == false && receipt.readBackConfirmed == true` 门禁，回执也如实写着上传 0/4、0/1。
**风险在命名与文档**：它自称「R09 判定的关键输入」，谁照这句话把它接进「结果待确认」
判定，演练（以及演练后被打断的路径）就会被误判成「可能已切头」。接之前先让它认得 `dryRun`。

## 6. 已知坑（照抄自 RULES.md，踩过）

- ⭐ `previousReleaseSeq` 必须传（取线上 `head.releaseSeq`）；`rootIndexHash` 每次重建都变
  → **别写「同输入同摘要」断言**（2026-10-07 沙盒演练连跑两次：`a4457c9c…` vs `6d0362b6…`）。
- ⭐ 网络失败 ≠ 内部错误：退出码 **7**，发布 `pendingConfirmation` 不可重试。
- ⭐ **禁 `import mimetypes`** —— 当年的沙盒必挂点（`/etc/apache2/mime.types` 被拒）。
  ✅ **2026-10-07 已在沙盒里复验修好**：发布演练 9/9，`build_release.py` 跑到发 `succeeded`。
- ⭐ CloudKit `save` **不是 upsert**：撞 `serverRecordChanged` 按「已存在」放行。
- ⭐ `fileExists` 在沙盒会骗人 → 唯一判据 `OpsBridgeSettings.isReadableFile(_:)`。
- ⭐ iOS 上传**不打日志** → 判定只能看任务表状态 + 线上 `releaseSeq`。
- ⭐ **Mac 的「日志落盘」只在视图层做**（`OpsCloudSyncView.persistLog`）→
  任何绕过视图的调用方（探针、将来的其它入口）都**不会**留 `bridge/logs/<runID>.log`。
- ⭐ 整包 tar 必须 `shop-catalog.json` + `images/<原文件名>`；
  **哈希命名会让 `local:` 引用悬空**。
- ⭐ dev 线上 seq 1 **不是受控发布器产物**（引用全 `local:`）→ 别当基线信任。
  （注：线上 seq 2 也**不是**「2 店家 / 9 系列 / 263 商品」——那是 seq 1；seq 2 只有 1 店家。）

## 8. 推进纪律

- 每步完成后把**命令 + 结果 + 判据**原样贴进当日工作日志，不写「已完成」四个字了事。
- 判据一律可复制可复现，拒绝「看起来对了」。
- 门控不过 → 停在原地补证据，不往下走。
- 切环境是高风险动作：切之前看 `head.environment`，切之后确认状态已清空。
