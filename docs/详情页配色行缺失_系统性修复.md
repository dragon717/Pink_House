# 详情页「配色」行缺失 —— 系统性根因修复（2026-09-23）

用户反馈：

> 后台发布了「生成色 / 粉紫色 / 蓝色」三个同款单品（段段方领 JSK）。
> 前端详情页只显示了标题「段段方领 JSK · 3色」和顶部的「生成色」标签，
> **完全没有「配色」这一行**。作为对比，「段段长Jsk」就做得很好，有「配色：红色 粉色」。
> 请全局修复同款多色商品详情页「缺失配色选择器」的系统性 Bug。

---

## 一、根因：同一件事有两个数据源

不是某处 `if` 写漏，而是**「这款有哪几色」这件事被两处各自算了一遍**：

| 位置 | 数据源 | 在 SPU/SKU 下的结果 |
| --- | --- | --- |
| 标题的「· N 色」 | 同款商品集合（`siblings.count + 1`） | **3** ✅ |
| 「配色」行 | `store.colors(forProduct:)` = **本商品自己的规格色** | **0 或 1** ❌ |

本项目已落地的结构是「同款不同色 = **多个独立商品**」（每个颜色要能单独加购、单独进心愿）。
于是：

- 本商品只有自己那一色 → 配色行最多 1 个 chip，而不是「这款有哪几色」；
- 若该商品**没有规格行**（只把颜色写进商品名，例如新表单里只填了「颜色名 + 图」没勾尺码）
  → `variants` 为空 → `colors == []` → **整行消失**。

这正好解释了用户的两张截图：标题理直气壮写「· 3色」，配色行却一行没有。
而「段段长Jsk」之所以正常，是它的两个颜色恰好存在**该商品自己的规格**里（旧形态：
一个商品自带多规格色），与同款商品集合无关 —— 属于「碰巧对」。

---

## 二、修法：把「同款商品集合」收敛为唯一来源

新增 `ItemManager/Services/ShopCatalog/ShopCatalogDesignPalette.swift`（nonisolated 可单测）：

```swift
// 同款其他颜色商品：同系列 + 同品类 + 同款式名 + 未归档，排除自己
static func sameDesignProducts(of:among:) -> [CatalogProduct]

// 同款颜色集合（去重保序）：本商品在前，其余依次追加
static func colors(of:among:explicitColors:) -> [String]
```

单个商品贡献颜色时**两种数据形态都要覆盖**：

1. **多规格色**（旧形态，即参考图里那条正常数据）→ 全部列出；
2. **单一颜色只写在商品名里**（新形态，没建规格行）→ 从商品名剥离颜色词兜底。

刻意**不**用「整名兜底」：名称里没有颜色词就不贡献颜色，
避免「大蝴蝶结背心裙」既当款式名又当颜色（这是项目既有硬规则）。

接线：

| 位置 | 变化 |
| --- | --- |
| `ShopCatalogStore` | 新增 `designColors(forProduct:)` —— 详情页「配色」行的唯一数据源；商品不在目录时退回本商品规格色 |
| `ShopCatalogProductDetailView.sameDesignSiblings` | 改走 `ShopCatalogDesignPalette.sameDesignProducts`，**删掉视图里那份重复过滤** |
| `ShopCatalogProductDetailView.colors` | `store.colors(forProduct:)` → `store.designColors(forProduct:)` |

至此**标题「· N 色」/ 配色行 / 轮播兄弟色**三者共用同一份同款商品集合，不可能再对不上。

### 刻意没动的地方

- 加购弹窗里的「配色」区块（`chipGrid`）仍然用 `colors(forProduct:)` ——
  那是**挑本商品要买哪个色号**的规格选择器，语义是「本商品的规格」，
  与「这款有哪几色」不同，合并会把别的商品的色号塞进购买记录。
- 点菜页本来就是对的：它的颜色 chips 取自**合并卡片内的同款商品组**（`group.products`），
  不是单个商品的规格色。

## 三、测试

`ItemManagerTests/ShopCatalogDesignPaletteTests.swift`，两类：

- `ShopCatalogDesignPaletteTests`（纯逻辑）：同款商品集合的判定与排除（跨系列 / 跨品类 / 不同款 / 已归档）、
  三色聚合且本商品在前、**规格色为空时退回名称颜色词**、旧形态多规格色保序、
  重复色只列一次、无颜色线索的商品不贡献但不影响其他色；
- `ShopCatalogDesignColorsStoreTests`（仓库层）：用**真实发布链路**产出三个同款颜色商品
  （表单一次录入 → 三条各自发布），断言每个商品的配色行都是整款 3 色，
  且 `designColors.count == 标题.colorCount`。

**核心不变量**（本次 Bug 的一句话形式）：

> 标题写「· N 色」，配色行就必须有 N 个颜色。
