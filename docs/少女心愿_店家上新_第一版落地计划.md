# 少女心愿「店家上新 / 历年系列」第一版落地计划

> 核心原则：**不改变少女心愿现有 UI 与导航结构，不把“店家上新”做成独立商城或新衣橱，而是把它作为现有「时光馆」中的公共商品档案入口，并深度联动现有少女衣橱、心愿尾款。**

---

## 1. 功能定位

「店家上新 / 历年系列」是少女心愿自己的 Lolita 商品档案库。

它负责：

- 查看店家当前上新；
- 查看店家往年系列；
- 查看系列下的商品；
- 查看商品图、配色、尺码、尺码表；
- 查看历史预约价与后续现货价；
- 将商品加入现有心愿；
- 将预约商品直接带入现有心愿尾款；
- 将已经拥有的商品直接写入现有少女衣橱；
- 将主裙 + KC + 袖套等多件商品合并成一个现有衣橱条目。

它**不提供购买链接、不做商城、不做支付、不做订单、不做物流。**

---

## 2. 必须遵守的产品边界

### 2.1 不改变现有少女心愿 UI

必须沿用当前：

- 页面背景；
- 粉色 / 金色视觉体系；
- 卡片样式；
- 字体层级；
- 圆角；
- 顶部导航；
- 底部导航；
- 衣橱详情；
- 心愿尾款；
- 按钮与交互习惯。

禁止为店家上新重新设计整个 App。

### 2.2 「时光馆」就是正式入口

现有底部导航：

```text
衣橱
心愿尾款
时光馆
我
```

其中：

```text
时光馆
```

就是本次功能正式入口。

不新增新的 Bottom Tab。

### 2.3 不提供用户购买入口

用户侧禁止出现：

```text
立即购买
去淘宝
前往店铺
购买链接
商品链接
支付
订单
物流
```

淘宝只作为运营录入资料的输入来源。

## 35. 淘宝解析原则

核心原则：

> 能拆多少拆多少，剩下人工补。

不能设计成“要么全成功，要么全失败”。

## 44. 强制开发约束

1. 不改变少女心愿现有 UI。
2. 不新增店家上新 Bottom Tab。
3. 时光馆就是正式入口。
4. 不做商城。
5. 不向用户暴露淘宝购买链接。
6. 不做支付、订单、物流。
7. 不做发货 / 收货状态。
8. Series 与 Product 必须分开。
9. 预约价不能被现货价覆盖。
10. Product 必须支持多个 SaleEvent。
11. Catalog 与用户衣橱数据必须分层。
12. 上新只能作为现有衣橱的数据入口。
13. WardrobeEntry 必须有主衣物。
14. 小物不能与主衣物平级决定主类型。
15. 主衣物决定主类型。
16. 小物写入现有衣橱小物区域。
17. 价格信息支持小物明细。
18. 旧衣橱必须兼容。
19. 商品图和尺码图必须保留可保存原图。
20. 淘宝解析只能生成草稿。
21. 淘宝解析失败不能阻塞手动补录。
22. 不重新实现一套心愿。
23. 不重新实现一套尾款。
24. 不重新实现一套衣橱。
