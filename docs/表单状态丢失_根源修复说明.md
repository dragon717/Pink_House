# 表单状态丢失（切后台 / 相册选图 / 切应用返回后内容全没）根源修复

> 需求 · 2026-09-24
> 用户原文：
> 「当 App 切到后台、跳转相册选图或切换到其他应用后，再返回该页面时，之前填写的所有内容全部消失，页面被重置为初始状态，用户必须从头重新填写，严重影响体验。请分析造成该问题的根本原因并修复，确保在上述任一场景下离开再返回页面时，所有已填写的表单字段和已选封面图都能完整保留并自动恢复显示。修复完成后，请针对以下场景逐一验证：仅切后台再返回、去相册选图后返回、切换到其他应用后返回。」

---

## 0. 结论先行

| 问题 | 根因（一句话） | 修法 |
|---|---|---|
| 离开再回来，表单被重置成初始状态 | ① `.sheet` 挂在 `ForEach` 的**行视图**上，行被复用时 sheet 的内容视图连同 `@State` 一起重建；② 上一轮加的 `loaded` 守卫**自己也是 `@State`**，视图一重建就归零 → 守卫失效、表单被存储值重新回填 | ① 结构：`.sheet` 提到稳定容器上只挂一次；② 兜底：新增「编辑中快照」，离开前落盘、重建后自动恢复 |

两条贯穿原则：

* **状态不能只活在 `@State` 里** —— 只要它的存活依赖视图身份，视图身份一变它就没了。要恢复的东西必须有一份落在磁盘上。
* **恢复不能静默** —— 恢复出来的是「用户上次没保存的编辑」，必须给一条一眼可见的说明 + 一键放弃的路（`放弃修改`），否则用户会以为「明明没保存，怎么自己变了」。

## 1. 根因：两层，缺一不可

### 1.1 证据一：上一轮的修复方向错了（且错得可复现）

`ShopCatalogSeriesEditSheet.swift` 的 `onAppear` 里留着上一轮的注释：

```swift
.onAppear {
    // 一次性回填（2026-09-24 状态丢失修复）：切后台回前台、进相册选图、
    // 切其他应用再返回都会重新触发 onAppear —— 无守卫时这里会用 series
    // 原始值覆盖用户已填的全部内容（表现为表单被重置）。与
    // ShopCatalogDraftDetailEditor 的 `loaded` 守卫同款：只在首次出现时回填。
    guard !loaded else { return }
    loaded = true
    name = series.name
    …回填…
}
```

上一轮把病灶判成了「`onAppear` 被重复触发」，所以用 `loaded` 一次性回填守卫去挡。
**但 `loaded` 是 `@State`** —— 真正的病灶是**承载它的视图被重建**：

```
视图被重建
  → loaded 回到 false（它是 @State，跟着视图生命周期走）
  → guard !loaded 通过
  → 整个表单被 series / draft 的存储值重新回填
  → 用户看到「内容全部消失，页面被重置为初始状态」
```

守卫和被守卫的东西**存在同一个生命周期里**，所以它挡不住「生命周期结束」这件事。

### 1.2 证据二：视图为什么会被重建 —— `.sheet` 挂在 `ForEach` 的行上

三处页面都是「`ForEach` 的行视图里挂 `.sheet`」：

| 页面 | 原来的写法 |
|---|---|
| 批次详情（整批归属 + 一站式系列配置） | `ShopCatalogOpsView.batchRow(_:)` 行尾 `.sheet(item: $selectedBatch)` |
| 补录草稿编辑器 | `ShopCatalogDraftEditorRow` 行内 `@State showsEditor` + `.sheet(isPresented:)` |
| 系列编辑页 | `SeriesManageRow` 行内 `@State showsEdit` + `.sheet(isPresented:)` |

`Form` / `List` 底层是**惰性、可复用**的列表容器。行身份一旦变化、或列表重新布局，
行视图就被重建 —— 而切后台、跳系统相册、切到其他应用再回来，这三件事**都会**让列表重新布局。

行视图一重建，挂在它上面的 sheet 的内容视图（`ShopCatalogBatchDetailView` /
`ShopCatalogDraftDetailEditor` / `ShopCatalogSeriesEditSheet`）随之重建，
里面的十余个 `@State`（含封面图引用、每个颜色的配色图）**一次性归零**。

这就是三个场景表现完全一致的唯一解释：它们触发的其实是**同一条重建路径**。

### 1.3 为什么「只有这三个场景」会丢

* **App 内正常导航返回**（点「完成」/ 返回上一页）：行没有重新布局，`@State` 还在；
* **切后台 / 相册 / 切应用**：视图层级被系统顶出前台，回来后列表重新布局 → 命中上面的重建路径。

## 2. 修复：结构 + 兜底，两层都要

### 2.1 第一层（消除诱因）· `.sheet` 从行视图提到稳定容器

**运营中心**（`ShopCatalogOpsView`）：三个 sheet 合并成一个页面级枚举驱动，只挂一次。

```swift
private enum OpsSheet: Identifiable {
    case manualBatch(CatalogBatchEntrySession)   // 手动录入新建批次
    case batchDetail(CatalogBatchEntrySession)   // 点批次行
    case draftEditor(CatalogProductDraft)        // 点草稿行
}
@State private var activeSheet: OpsSheet?

// 挂在 content 上（稳定容器），不再挂在任何一行上
.sheet(item: $activeSheet) { sheet in
    switch sheet {
    case .manualBatch(let batch), .batchDetail(let batch):
        ShopCatalogBatchDetailView(draftStore: draftStore, store: store, batch: batch)
    case .draftEditor(let draft):
        ShopCatalogDraftDetailEditor(draft: draft, draftStore: draftStore, store: store)
    }
}
```

`ShopCatalogDraftEditorRow` 的 `showsEditor` + `.sheet` 删除，改成 `var onOpenEditor: (() -> Void)?` 回调。

**实体管理**（`ShopCatalogOpsManageView`）：`SeriesManageRow` 的 `showsEdit` + `.sheet` 删除，
改成 `onEdit` 回调；`editingSeries: CatalogSeries?` 提到页面级。

> 顺带修掉一个隐患：原来 `OpsSheet` 之前，`batchRow` 里每一行都挂了一个 `.sheet(item: $selectedBatch)`，
> 5 行就有 5 个 sheet 绑同一个状态 —— SwiftUI 只让第一个生效，是未定义行为。

### 2.2 第二层（兜底）· 编辑中快照

新增 `ItemManager/Services/ShopCatalog/ShopCatalogFormSnapshotStore.swift`：

* `ShopCatalogFormSnapshotStore`（`nonisolated`，可单测）
  `save` / `load` / `clear` / `clearAll`，落在 `ShopCatalogStorage.directory/form-snapshots/`。
  文件名 = 作用域白名单化 + **FNV-1a 稳定哈希后缀**（不同 id 被擦成同样字符时也不会互相串页）。
  读 / 写 / 坏文件一律**不抛错**：快照是兜底，它坏了绝不能让用户连页面都进不去。

* `ShopCatalogFormSnapshotKeeper<Snapshot>`（`@MainActor` 值类型，放 `@State`）
  把「防抖落盘 / 立即落盘 / 提交清理 / 自动恢复」收在一处，三个页面共用同一份实现。

* 三个页面载荷（`Codable`）：
  `ShopCatalogBatchConfigSnapshot`（带 `batchID` 归属判定）·
  `ShopCatalogDraftFormSnapshot`（带 `sourceDraftID`）·
  `ShopCatalogSeriesEditSnapshot`（带 `seriesID`）。

**四条状态机口径**：

| 时机 | 动作 |
|---|---|
| 变更后 **0.5s 防抖** | `schedule` → 落盘。**这是相册场景的唯一兜底** —— 相册返回不走 `onDisappear` |
| `scenePhase != .active` / `didEnterBackgroundNotification` / `onDisappear` | `flush` → 立即落盘 |
| 重新出现（`onAppear`，且 `loaded` 已归零 = 视图确实被重建过） | `restoreOrDiscard`：快照与「按存储值填出的默认态」**逐字段相同**就丢弃（不弹无意义提示），有差异才恢复并置 `didRestore` |
| 保存成功 | `commit` → 记住「这就是已提交的内容」+ 清快照。此后关页的 `flush` 只会清、不会把已保存内容又写成「未保存的编辑」 |

**恢复提示条**（不静默恢复）：`已恢复上次未保存的编辑` + 说明 + `知道了` / `放弃修改`。

### 2.3 顺带修掉的一个「恢复会被立刻抹掉」的坑

批次详情页原来用 `.onChange(of: seriesID)` 回填年月框。这对**程序化赋值**同样会触发 ——
快照恢复出来的年月会被「按系列重新推导」立刻覆盖，表现为「恢复了但年月没了」。
改成挂在 Picker 自己的 `Binding` setter 上（`seriesSelection`），
「谁改的」一目了然；`ensureSeriesForConfig()` 里改为显式回填一次。

## 5. 兼容与边界

* 快照是**新增的独立目录**（`form-snapshots/`），不与草稿 / 覆盖层 / 种子数据共用任何文件，
  也不改任何既有 Codable key —— 零迁移；
* 只加了 `Codable` **遵循**（`ShopCatalogSeriesConfigForm` / `ColorRow`），没有增删字段、
  没有改 key，既有 JSON 读写行为逐字不变；
* `.sheet` 的呈现位置变了，**呈现内容与时机不变**；
* 快照的 `scope` 一定带实体 id（批次 id / 草稿 id / 系列 id），换实体一律丢弃 —— 不存在串页；
* 快照不会无限累积：`commit` 后即清；每个作用域最多一个文件，`clearAll()` 可整体重置。

**未做（明确说明）**：

* 没有做「跨启动恢复」之外的清理策略（例如超过 N 天的陈旧快照自动过期）——
  当前口径是「保存成功即清」+「与存储值相同即清」，正常使用不会留垃圾；
* 店家编辑页（`ShopCatalogShopEditSheet`）与商品编辑页**未接快照** ——
  它们的 sheet 仍挂在行上（同类反模式）。本轮聚焦用户报告的链路
  （批次详情 / 补录编辑器 / 系列编辑页），这三页已连根处理；
  其余页面建议后续按同一模式收口。

### 6.4 排查过程中出现过的三次「假失败」（都在驱动侧，不是 App 缺陷）

这三条都真烧掉过整轮运行时间，写在这里免得后面再撞：

1. **点导航栏标题收不掉 SwiftUI 键盘。** 打字后键盘一直留在屏幕上，把「创建 / 确认系列并开始配置」
   压在下面 → `isHittable == false` → 怎么滚都点不到，症状是「元素明明 `exists` 就是点不中」。
   收键盘必须用回车（`app.typeText("\n")`，single-line `TextField` 没设 `onSubmit` 时会失焦）；
   兜底才切后台再回前台。
2. **测试自己把 sheet 关掉了。** 「尝试关掉相册」的白名单里带了 `完成 / Done`，
   而 `批次详情` sheet 导航栏右上角**就是**「完成」→ 点下去 sheet 直接关闭，
   后面两个场景全报「状态丢失」。日志铁证：`t = 203.52s Tap "完成" Button`。
   教训：给「可能存在的系统弹窗」准备的白名单，**绝不能包含宿主页面自己的按钮文案**。
3. **`isHittable == true` ≠ 点上报 frame 的几何中心能中。**
   `添加封面图片` 是 `.buttonStyle(.bordered)` + `PhotosPicker`，在整行里靠左：
   上报 frame `(16, 743, 370, 59.7)`，真实可点区域只有药丸 `(32, 758, 141.7, 29.7)`
   —— 中心 x=201 已在药丸外，点下去毫无反应（相册三处截图都显示没打开）。
   改成 **dx≈0.25 / dy≈0.4** 后相册第一次检查就出现。
   顺带确认：**PHPicker 虽在独立进程，但元素在 `app` 层级里可见**（`app.buttons["取消"]` 立刻可查），
   不需要 `XCUIApplication(bundleIdentifier: "com.apple.mobileslideshow")`。
