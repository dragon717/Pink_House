# 现有业务流程文档

## 1. 概述
本文档描述了“少女心愿”物品管理系统的核心业务流程，重点在于“三坑”（Lolita、JK、汉服）服饰的录入与财务管理。

## 2. 核心流程

### 2.1 物品录入流程
用户手动添加一件新物品（如裙装）的操作路径：

1.  **触发动作**：点击首页“+”按钮进入“手动添加裙装”页面。
2.  **基本信息录入**：
    *   **裙装名称** (必填)：输入文本。
    *   **品牌名称** (选填)：输入文本。
    *   **类型** (选填)：支持多选或输入，如 JSK, OP, SK。
    *   **颜色** (选填)：支持多选或输入，如 粉色, 白色。
    *   **尺码** (选填)：支持多选或输入，如 S, M, L。
    *   **小物** (选填)：配套饰品记录，如 BNT, 发带。
3.  **多媒体录入**：
    *   **选择图片**：支持从相册选择最多 9 张图片。
    *   **主图设置**：默认第一张为主图。
4.  **标签管理**：
    *   **选择标签**：从现有标签池选择。
    *   **新建标签**：支持快速创建新标签分类。
5.  **社交同步** (可选)：
    *   开启“同步到裙装广场”开关（分享功能）。

### 2.2 财务与定金尾款流程
针对预售类商品的特殊财务管理：

1.  **价格录入**：
    *   **裙装总价**：自动计算或手动输入。
    *   **定金**：输入已支付定金金额。
    *   **尾款**：输入待支付尾款金额。
    *   **小物总价**：输入配套小物总金额。
2.  **购买信息**：
    *   **购买日期**：选择日期选择器。
    *   **备注**：文本输入框。
3.  **补款逻辑** (隐式流程)：
    *   若存在“定金”且“尾款”未结清，系统应标记该物品为“待补款”状态。
    *   用户需设置预计补款时间（需在后续开发中明确此交互，目前截图中未直接体现，建议补充）。

## 3. 状态流转
*   **草稿/新建** -> **已付定金** (填写了定金，尾款待付) -> **已完成** (全款付清) -> **已发货/已收货** (可选后续扩展)。

## 4. 异常流程
*   **必填项缺失**：点击保存时，若“裙装名称”为空，通过 UI 提示（红色边框或 Toast 提示）阻断提交。
*   **数据格式错误**：价格字段仅允许输入数字和小数点。
