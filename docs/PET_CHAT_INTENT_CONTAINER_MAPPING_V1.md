## 1. 目标

- 支持模糊触发（不依赖精确口令）
- 多意图时按优先级和主意图分流
- 无法稳定判断时返回 A/B/C 引导选项

## 2. 意图优先级（高 -> 低）

| 优先级 | 意图类型 | 典型触发 | 目标容器 |
|---|---|---|---|
| P0 | 待确认流程续操作 | 确认 / 取消 / 就这个 | 当前流程容器 |
| P1 | 交易动作 | 充值 / 购买 / 二胎领养 | 交易确认容器 |
| P2 | 宠物动作 | 喂食 / 清洁 / 切换宠物 | 行为执行容器 |
| P3 | 面板请求 | 状态 / 货币 / 背包 / 商店 / 数钱 | 信息或交互面板容器 |
| P4 | 信息建议 | 天气+穿搭 / 库存查询 | 并列信息容器 |
| P5 | 泛聊陪伴 | 安抚 / 闲聊 | 轻交互文本容器 |

## 3. 模糊触发（口语化识别）

识别采用联合评分：
- 关键词簇匹配（同义表达）
- 句式意图（请求、确认、操作、查询）
- 上下文状态（是否处于待确认流程）
- 历史短期上下文（上一轮容器类型）

### 3.1 同义词簇（节选）

- 充值：`充值/充币/买币/氪金/加点喵币`
- 二胎：`养二胎/再养一只/领养第二只/再来一只`
- 切换：`我切换/换一只/换奶茶/换毛毛`
- 喂食：`吃猫粮/喂猫粮/来个罐头/给它吃点`
- 状态：`看看状态/它现在咋样/我家宝怎么样`

## 4. 多意图冲突处理

1. 对候选意图打分，得到 Top1/Top2/Top3。  
2. 若 `Top1 - Top2 >= delta_main`：直接执行 Top1。  
3. 若分差不足或跨域冲突（如“二胎 + 充值”）：进入分流引导。  

## 5. A/B/C 引导气泡规则

- 仍走单气泡容器（不额外再弹一个泡）。
- 选项结构：
  - A：最高置信候选
  - B：第二候选
  - C：兜底（第三候选或“都不是，我换个说法”）

### 5.1 示例

输入：`我想领养二胎想充值`
- A 我想充值
- B 我想领养二胎（60喵币）
- C 先看看我当前喵币余额

## 6. 意图到容器映射（首版）

| 用户主要意图 | 默认容器 | 结果回写 |
|---|---|---|
| 首次领养 | 领养选择容器（滑动选奶茶/毛毛） | 写入当前宠物身份 |
| 二胎领养 | 二胎确认容器（60喵币） | 扣费 + 新增宠物 |
| 切换宠物 | 宠物切换容器 | 切换 active 宠物 |
| 喂食/道具使用 | 背包交互容器 | 更新库存与属性 |
| 商店购买 | 商店交互容器 | 更新库存与货币 |
| 数钱 | 数钱交互容器 | 展示/回写裙装总价值 |
| 查状态 | 状态面板容器（4+1） | 可触发建议动作 |
| 查货币 | 货币信息容器 | 展示三币种余额 |
| 天气+穿搭 | 并列信息容器 | 同泡展示，不拆泡 |

## 7. 上下文继承规则

- 上一轮在“确认流程”中，本轮短句默认优先解释为续操作。
- 用户明确改口（如“先不领养，先充值”）时，清理旧流程上下文并切换主意图。

## 8. 回退策略

- 低置信度且无稳定候选：直接返回 A/B/C 引导。
- 用户选择“都不是”：返回开放输入提示，并给 2~3 个可执行建议。

## 9. 观测指标（路由侧）

- 多意图分流触发率
- 分流后一次点击解决率
- 意图误判回退率
- 主意图识别稳定率

容器具体结构与布局由渲染层协议定义，详见：
