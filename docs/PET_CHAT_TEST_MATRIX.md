# 萌宠对话测试矩阵

> 迁移日期：2026-05-25
> 迁移来源：历史 `temp/对话/萌宠人工测试或mcp测试.md`
> 当前状态：测试矩阵已迁入正式 docs；本文不声明相关功能均已实现，执行前应先对照 `docs/PET_CHAT_REFACTOR_EXECUTION_PLAN.md` 与当前代码确认能力边界。

## 1. 测试目标

萌宠对话验收按四个维度展开：

- 识别：用户自然语言是否进入正确意图和路由。
- 展示：聊天气泡、内嵌卡片、按钮和表情图是否正确。
- 行为：按钮点击后是否真的执行功能并回写状态。
- 体验：陪伴语气自然，不生硬、不抢答、不乱跳业务。

## 2. 测试准备

| 项目 | 准备内容 |
|---|---|
| 宠物 | 至少两只，例如 `奶茶`、`毛毛` |
| 低状态组 | 饱食 20、精力 30、心情 35、亲密度 20 |
| 高状态组 | 饱食 90、精力 90、心情 90、亲密度 80 |
| 时间段 | 深夜 `23:00-05:59`、清晨 `06:00-07:59`、白天 `08:00-22:59` |
| 基础数据 | 背包有吃 / 喝 / 玩 / 清洁道具；商店可购买；至少 3 件可搭配衣服；存在一组最近搭配记录 |

建议至少覆盖这些时间和精力组合：

| Case | 时间 | 精力 | 期望 |
|---|---:|---:|---|
| T1 | 02:00 | 90 | 深夜仍允许偏困倦表达 |
| T2 | 05:59 | 90 | 深夜边界仍按深夜处理 |
| T3 | 06:30 | 60 | 清晨精力低于 65，允许困倦倾向 |
| T4 | 06:30 | 70 | 清晨精力较高，不应误判极困 |
| T5 | 07:59 | 64 | 清晨边界，低于 65 可困倦 |
| T6 | 08:00 | 64 | 白天边界，不应继续按清晨阈值判断 |
| T7 | 14:00 | 34 | 白天精力低于 35，应困倦 |
| T8 | 14:00 | 35 | 白天阈值边界，不应强行困倦 |

## 3. 主流程矩阵

每只宠物分别跑低状态和高状态：

| 步骤 | 输入 / 操作 | 验收点 |
|---|---|---|
| P1 | 进入萌宠对话页 | 默认欢迎、皮肤、头像正常 |
| P2 | `你在干嘛` | 闲聊识别正确，语气符合当前宠物 |
| P3 | `我有点焦虑，先安慰我` | 进入情感支持，不生硬说教 |
| P4 | `我有点焦虑，然后帮我搭一套出门穿搭` | 识别混合意图，先安慰再处理穿搭，不冷启动业务 |
| P5 | `帮我看全部货币余额` | 出现货币信息容器或正确入口 |
| P6 | 点击内嵌卡片按钮 | 功能真实执行，不只是文字回复 |
| P7 | `你现在心情怎么样` | 状态读取正确，语气与状态匹配 |
| P8 | `它是不是有点渴，也有点低落` | 多状态识别正确，不串到无关能力 |
| P9 | `帮我抽一签` | 抽签容器 / 文案正确 |
| P10 | `今天天气怎么样，帮我搭一套` | 天气与穿搭在同一轮内合理呈现 |
| P11 | `刚刚搭配的三件衣服价格多少` | 追问拿最近一次搭配，不编造 |
| P12 | `切换到毛毛` / `我要奶茶` | 宠物切换成功，名字、人设、上下文不串 |
| P13 | 回到聊天继续追问 | 上下文稳定，当前宠物身份正确 |

## 4. 意图测试语句

| 分类 | 测试语句 |
|---|---|
| 情感支持 | `我有点焦虑，先安慰我` / `今天压力好大` / `我有点低落` / `先陪陪我` |
| 情感 + 功能混合 | `我有点焦虑，然后帮我搭一套` / `先安慰我，再看天气穿搭` / `我现在有点烦，但也想看上一套价格` |
| 货币 / 财务 | `帮我看全部货币余额` / `喵币还有多少` / `鱼币还有多少` / `骨头币还有多少` |
| 背包 / 商店 | `打开背包看看道具` / `去商店补货` / `猫粮还有吗` |
| 数钱 | `帮我数一下人民币` / `帮我数一下美元钞票` / `帮我数一下日元` / `数数我的裙装总价值` |
| 抽签 | `帮我抽一签` / `来一签` / `看看今日运势` |
| 状态总览 | `帮我看看萌宠现状` / `显示全部状态` / `状态总览` |
| 单项状态 | `你饿了吗` / `它是不是有点渴` / `它脏不脏` / `你现在心情怎么样` / `它今天有点低落吗` / `你喜欢我吗` |
| 穿搭 | `帮我搭配一套出门穿搭` / `今天天气怎么样` / `帮我找裙子` / `刚刚搭配的三件衣服价格多少` |
| 宠物切换 | `我要毛毛` / `切换到奶茶` / `团子今天在吗` |

## 5. 状态专项

| 状态 | 输入 | 期望 | 操作后复验 |
|---|---|---|---|
| 饱食低 | `你饿了吗` | 先说明饿不饿，再给背包 / 商店按钮 | 喂食后数值和文案刷新 |
| 饮水低 | `你是不是有点渴` | 显示饮水卡片，不跑去讲心情 | 喝水后数值和文案刷新 |
| 清洁低 | `你脏不脏` | 出现清洁建议和操作入口 | 清洁后状态刷新 |
| 心情低 | `你现在心情怎么样` | 先共情，再建议，不直接教育 | 互动后心情反馈变化 |
| 亲密度低 / 高 | `你喜欢我吗` | 桃心显示与语气差异合理 | 亲密度变化后反馈更新 |

## 6. 体验问题排查

重点找这些问题：

- 同一句话多个意图时是否乱跳。
- 安慰场景是否直接推业务。
- 内嵌卡片按钮文案是否像用户语言，而不是系统命令。
- 切换宠物后名字、表情、人设是否串。
- 追问上一套价格时是否取最近搭配。
- 没有数据时是否诚实说明，而不是编造。
- 抽签、数钱、背包、商店等能力是否真实执行。
- 连续 10 轮后是否明显重复句式。
- 是否突然承认自己是 AI、模型、云端助手。
- 情感支持是否连续追问过多，让体验变差。

## 8. 最低上线标准

- 情感支持 10 条里，0 条出现生硬说教。
- 内嵌功能 10 条里，至少 9 条路由正确。
- 时间段 8 组里，困倦逻辑全对。
- 状态卡片 5 类里，展示和按钮全对。
- 切宠物和上下文追问不串角色、不串记忆。
