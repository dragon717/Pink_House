## 0. 一句话结论

把底部 Tab「时光馆」从当前「梦裙编年史 + 多模式图鉴 + 双品牌双管道」的杂糅状态，重构为与「少女心愿」完全同构的 **Lolita 店家商品档案库**：时光馆首屏即「店家上新」，公共 Catalog（Shop / Series / Product / Variant / SizeChart / SaleEvent / Asset）+ 用户私有状态（心愿 / 尾款 / 衣橱）以 ID 引用 + 白名单运营（草稿→提交→审核→发布→归档）。旧编年史与 Midsummer 数据一次性迁入 Catalog，旧视图归档下线，**不重写心愿 / 尾款 / 衣橱底层**。

## 2. 目标定位

> **时光馆 = 少女心愿自己的 Lolita 店家商品档案库的正式入口（店家上新馆 + 品牌年鉴馆）。**

- 首屏即「店家上新」：看店家当前上新、翻历年系列年鉴、查商品档案（图/配色/尺码/尺码表/历史价格）。
- **不是商城**：无购买、无支付、无订单、无物流、无淘宝跳转；普通用户仅查看 + 加入心愿 / 尾款 / 少女衣橱。
- 运营由白名单 `CreatorAccess` 管控，入口 `设置 → 运营工具 → 店家商品库`，普通用户不可见。
- 底部导航不变：`衣橱 / 心愿尾款 / 时光馆 / 我`。

## 5. 关键数据结构

### 5.1 公共 Catalog（复用 `ShopCatalogModels.swift`，仅一处增补）

| 实体 | 字段 |
|---|---|
| `CatalogShop` | id, name, aliases[], logo, cover, description |
| `CatalogSeries` | id, shopID, name, year, season, cover, description |
| `CatalogProduct` | id, shopID, seriesID, name, category, images[], description |
| `CatalogProductVariant` | id, productID, color?, size? |
| `CatalogSizeChart` | id, productID, unit, columns, rows, sourceImage |
| `CatalogSaleEvent` | id, productID, type(reservation/stock/rerelease), price, deposit?, balance?, startAt?, endAt? —— **追加式，永不覆盖** |
| `CatalogAsset` | id, type, thumbnailURL?, previewURL?, originalURL, width, height |

派生只读视图：`CatalogPriceArchive`（预约/现货各取最近一条 → 差价与百分比）。

**G3/G4 增补（唯一模型改动）**：`CatalogShop` / `CatalogSeries` / `CatalogProduct` 各加一个可选字段

```swift
var archivedAt: Date? = nil   // 归档标记；nil = 未归档。decodeIfPresent 兜底，旧 JSON 完全兼容
```

- 归档 ≠ 删除：被引用实体禁止物理删除，只能写 `archivedAt`。
- 查询层约束：`ShopCatalogStore` 全部用户侧查询（列表/主页/系列/详情/搜索）追加 `archivedAt == nil` 过滤；运营端查询不过滤。
- 用户侧引用不受影响：`Clothing.catalog*` 指向已归档实体时，商品详情仍可从衣橱记录进入（或显示「已下架归档」占位），绝不丢数据。

### 5.2 用户私有状态（复用，不重写）

`Clothing.swift:150-152` 三个可选引用字段即全部关联：

```swift
var catalogProductID: String?
var catalogVariantID: String?
var catalogSaleEventID: String?
```

- 心愿 = `Clothing`（无 isDepositPlan）+ catalogProductID；
- 尾款 = `Clothing.isDepositPlan=true` + deposit/balance/finalPayment* 字段（现有状态机原样使用）；
- 衣橱 = `Clothing` / `AccessoryItem`，由 `ShopCatalogWardrobeInserter` 落库并回填引用字段。
- **用户私有状态通过 ID 引用 Catalog，不复制公共档案冗余数据。**

### 5.3 覆盖层合并规则升级（支撑「编辑已发布实体」）

现状 `rebuildMergedCatalog` 是「同 id 跳过」——无法表达运营编辑已发布实体。升级为：

- `shops / series / products / variants / sizeCharts / assets`：覆盖层**同 id 实体整体替换**基底（后写胜出）；
- `saleEvents`：**永远追加**，不做替换（销售历史不可覆盖，硬约束）；
- 归档：运营对已发布实体归档 → 覆盖层写入带 `archivedAt` 的同 id 实体 → 替换后用户侧自然过滤。

### 5.4 批次录入会话（G1 新增）

```swift
struct CatalogBatchEntrySession: Codable, Identifiable {
    var id: String                    // "batch-<uuid8>"
    var shopID: String?               // 选定归属店家（可 nil 用 newShopName 新建）
    var newShopName: String
    var seriesID: String?
    var newSeriesName: String
    var newSeriesYear: Int?
    var newSeriesSeason: String
    var entries: [CatalogProductDraft]   // 每个单品一条独立草稿，状态互不耦合
    var createdAt: Date
    var sourceTexts: [String: String]    // draftID → 原始淘宝文本（仅运营侧留存，绝不透出用户端）
}
```

- 持久化：`Application Support/ShopCatalog/shop-catalog-batches.json`；批次内草稿仍复用 `CatalogProductDraft` 并写入现有 `shop-catalog-drafts.json`（看板/状态机零改动）。
- `CatalogProductDraft` 增补字段（G5，全部可选、向后兼容）：`images: [CatalogAsset]`、`variants: [CatalogProductVariant]`、`sizeChart: CatalogSizeChart?`。
- 淘宝批量导入：`ShopCatalogTaobaoParser.parse` 保持单条 API，新增 `parseBatch(texts: [String]) -> [(draft, error?)]` 循环封装，逐条容错。

### 5.5 引用保护判定（G3 核心规则）

```text
被引用(product) = 存在 Clothing.catalogProductID == product.id（含软删除记录，deletedAt 不豁免）
被引用(series)  = 该系列下存在任意 product（含已归档）或上述 product 引用
被引用(shop)    = 名下存在任意 series/product 或上述引用
可物理删除      = !被引用 && 无下级实体；否则仅可归档
```

实现位置：`ShopCatalogOps.swift` 新增 `ShopCatalogReferenceGuard`，运营 UI 在删除动作前调用，被拦截时提示「已被用户数据引用，仅可归档」。

### 5.6 旧 TimeHall 资产 → Catalog 迁移映射（一次性迁移工具）

> 工具：`tools/timehall_migration/migrate_timehall_to_shop_catalog.py`（附 `test_migration.py` 6 项单测，已全部通过）。
> **体量决策（实施中确认）**：`--scope catalogue`（默认）只迁画册年鉴（历年系列 + 展品，产物 152KB，可直接并入 Bundle 种子）；`--scope full` 额外迁全量在售清单（30MB / 4876 商品 / 62074 资产引用），**不进 Bundle**，留给 Phase 6 云端分发（THDataPack）。资产只保留真实商品图/封面，`imageSourceURLs` 来源引用链接不进资产。

| 旧实体（TimeHall V3 DTO） | 迁移去向 | 说明 |
|---|---|---|
| pinkHouse 编年史 `CatalogueDTO` / `ArchiveCatalogueDTO` | `CatalogSeries`（year/season/cover） | pink-house 作为一个 `CatalogShop` |
| `TimeHallItemDTO`（kind dress/clothing/accessory, productCode） | `CatalogProduct`（category 按 kind+styles 映射） | **保留原 productCode 作为新 CatalogProduct.id 种子**（稳定标识） |
| `TimeHallCommerceItemDTO.priceTiers`（含 depositJPY/balanceJPY） | `CatalogSaleEvent`（stock/reservation + price/deposit/balance） | 每条 tier 一条事件，全部保留不覆盖 |
| `TimeHallCommerceItemDTO.sizeChart` | `CatalogSizeChart` + `sourceImage` → `CatalogAsset` | 原图必须保留 originalURL |
| `TimeHallMerchant`（midsummerTale） | `CatalogShop`「仲夏物语」 | MidsummerSeries/MidsummerItem → CatalogSeries/CatalogProduct |
| `StoryDTO` / `CoordinateDTO` / `EventDTO` / `HistoryEntryDTO` | **不迁移** | 编年史叙事内容随旧馆归档；运营后续需要时按 Catalog 结构手动补录 |
| 收藏 `timeHall.treasured.v1`（UserDefaults） | 对应用品的心愿记录（**心愿尾款口径**：`PriceMode.wishlist`，isDepositPlan=true、定金 0、全款记待付尾款；§7 收尾更正——文档初稿写 isDepositPlan=false 与运行时「已拥有」判定冲突，2026-09-21 用户确认按心愿尾款口径执行） | 无法匹配的收藏保留在旧馆归档数据中不丢 |

## 8. MVP 验收标准（对齐 V1.1 文档 §5）

**用户端**
1. 时光馆 Tab 首屏即店家上新；可浏览店家上新、历年系列；查看图片、配色、尺码、尺码表；同屏查看预约价、现货价与差价。
2. 可加入心愿、加入少女衣橱；系列页支持多选多品类商品加入衣橱。
3. 心愿尾款状态仅：我已经预约、已付定金、待付尾款、尾款完成；无已发货、已收货。
4. 页面无任何购买链接/淘宝跳转。

**运营端**
5. 白名单可见运营入口，普通用户不可见；淘宝源链接不透出。
6. 一次补录任务录多单品、多品类混合；多条淘宝链接批量导入生成草稿，部分失败不阻断。
7. 店家/系列/商品可编辑；删除/归档严格按引用保护执行（被引用 → 仅归档；归档后用户端隐藏、用户已收藏记录保留）。
8. 草稿‑提交‑审核‑发布‑归档完整；批量提交、单品粒度审核（部分通过/部分驳回）。
9. 手动录入可完整完成全部业务（含图片/配色尺码/尺码表/销售事件），不依赖淘宝解析。

## 9. 开发硬性约束（复述 + 新增）

1. 不重写心愿、尾款、衣橱底层逻辑，只靠 `Clothing` 的 3 个 catalog* 引用字段关联。
2. Series 与 Product 不可合并；一个系列下多条单品。
3. SaleEvent 追加式，历史价格永不覆盖。
4. 一切关联用数据库 id；商品名称不能作为稳定唯一 ID（productCode 仅可作 id 种子）。
5. 被用户心愿/衣橱/尾款引用过的 Catalog 实体只能归档，禁止物理删除。
6. 淘宝解析只输出草稿，绝不自动发布。
7. 用户侧不透出任何购买/跳转淘宝链接。
8. 【新增】旧 TimeHall/Midsummer 数据只迁不删：迁移工具必须输出报告，CloudKit 公共库数据保留不动。
9. 【新增】`ThemeSkinSlot`、主题皮肤、底部导航等既有结构一律不动。
10. 【新增】`archivedAt` 字段必须 decodeIfPresent 向后兼容，旧 JSON / 旧备份不做破坏性迁移。

## 11. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 迁移丢数据 | 迁移工具输出逐实体报告；原 Bundle 种子与 CloudKit 数据不删；id 冲突以 override 追加策略兜底 |
| 收藏迁移失配 | 无法匹配项保留在归档数据中，报告列明供运营手工处理 |
| 覆盖层「同 id 替换」误伤种子数据 | 替换仅对运营显式编辑过的实体发生；种子文件只读；替换规则有单测覆盖 |
| 归档过滤遗漏导致已归档商品可见 | 查询层统一在 `ShopCatalogStore` 收口（不散落在视图层）；补归档过滤单测 |
| 旧馆用户习惯突变 | Phase 1 过渡期保留「馆藏档案」只读入口，公告引导后再下线 |
| 3469 行拆分引入回归 | 拆分仅移动代码不改逻辑；现有 TimeHall 快照/列表测试 + 首屏冒烟测试兜底 |
| 回滚 | 分阶段提交；Phase 1 仅改挂载点，revert 单 commit 即回旧首屏；Phase 2 模型字段全部向后兼容 |
