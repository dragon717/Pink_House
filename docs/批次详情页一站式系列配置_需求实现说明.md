# 批次详情页「一站式系列配置」需求实现说明（2026-09-24）

> 需求：重构批次详情页，把**系列编辑页**里的「发售阶段 / 图文（视觉与简介）/ 预约价格表」
> 三项配置整体迁移并集成到批次详情页，实现一站式配置；保存时保证**批次数据与所属系列数据
> 同步更新**；UI 上给出明确的「同系列共用」提示；发售阶段新增「尾款中」；「预约中」时新增
> **尾款时间**填写项（支持大致时间 / 具体时间）。

---

## 0. 本工程语境下的「前后端」

| 需求用词 | 本工程对应 |
|---|---|
| 前端 | SwiftUI 视图层（`ItemManager/Views/ShopCatalog/*`） |
| 后端 | 服务层 + 持久化：`ShopCatalogDraftStore`（草稿/批次/覆盖层写入口）、`ShopCatalogStore`（读取与合并视图）、JSON 覆盖层文件 |
| 「数据同步」 | 覆盖层（`shop-catalog-override.json` / `shop-catalog-batches.json` / `shop-catalog-drafts.json`）与内存视图的同源更新；**没有服务端**，所以「同步」= 单点写入 + 引用归一 + 一次落盘 |

持久化事实（决定了同步方案）：
- 系列实体住在**覆盖层**（`series[]`），批次与草稿住在另外两个 JSON；
- 三者的关系是**引用**（`draft.seriesID` / `batch.seriesID` / `product.seriesID`），**不是副本**。

## 2. 数据同步机制（需求一）

**结论：三项配置在全系统只有一处存储 —— `CatalogSeries`。批次里没有副本，所以「写一次」就是「全批次、全单品同步」。**

同步靠三件事保证：

1. **单一写入点**
   两个入口（批次详情页、系列编辑页）都只调用 `configForm.apply(to: series)` 组装，
   再经 `ShopCatalogDraftStore.saveSeriesConfig` / `upsertEntity` 落到唯一的覆盖层数组。
   两个入口共用**同一个表单类型与同一段 Section 代码**，不存在「一边少写一个字段」的可能。

2. **引用归一（本次新增的关键一步）**
   `saveSeriesConfig(_:batchID:)` 会把该批**仍然未自报系列**（`seriesID == nil`，即继承整批归属）
   的未发布草稿显式写成本次配置的系列 id。此后它们的归属不再依赖
   「批次当前选择」这层间接引用，改批次归属也不会把配置带走。
   - 已发布 / 已归档草稿不动（产物已在覆盖层）；
   - **自报系列的草稿不动**（单品页自己改过归属，既有裁定：自报系列优先）。

3. **一次落盘 + 失败可见**
   写顺序是「先覆盖层（配置）、后草稿（链接）」：覆盖层失败则草稿一条都不改并抛错；
   草稿写失败由 `upsert(_:)` 的整批持久化语义保证「要么全成功、要么磁盘不变」。
   UI 如实汇报同步条数（0 条也会明说，不假装成功）。

`ensureAttributionEntities` 另有一条与发布强绑定的口径：**同名系列复用而不是新建**
（与 `publish` 共用 `ShopCatalogDraftValidator.findExistingSeries`）。
若这里各写一套，运营会看到「批次里配好价格的系列」与「发布后出现的系列」是两条。

## 3. 状态流转设计（需求三）

### 3.1 阶段定义（四个可选 + 一个「未设置」）

| 阶段 | 业务含义 | 加购主推引导 |
|---|---|---|
| 未设置 | 旧数据 / 运营未填 → 沿用销售记录档期推导（行为与改动前一致） | 不变 |
| 预约中 | 预约（收定金）窗口进行中 | 定金 + 尾款（`depositPaid` 默认选中） |
| 预约已结束 | 预约窗口已关，**尾款还没开始收** | 预约价全款（`fullPaid` 默认选中） |
| **尾款中（新增）** | **正在收尾款**（已到尾款时间，或运营显式声明） | **定金 + 尾款**（补尾款的动作，与预约中同族） |
| 现货 | 直接按现货价入橱，不走定金 / 尾款 | 现货全款 |

> 「预约已结束」与「尾款中」必须分开：否则运营无法表达
> 「预约收了定金，现在正在等大家补尾款」这条事实。

### 3.2 触发条件与流转表（`CatalogSeriesSalePhaseResolver.effectivePhase`）

| 声明值 | 条件 | 生效阶段 |
|---|---|---|
| 未设置 | — | `nil`（不替运营决定） |
| 预约中 | 未填预约结束时间 | 预约中（缺依据就不猜） |
| 预约中 | 当前 ≤ 预约结束时间 | 预约中 |
| 预约中 | 已过预约结束时间 + 具体尾款时间**已到** | **尾款中** |
| 预约中 | 已过预约结束时间 + 其余情况 | 预约已结束 |
| 预约已结束 | 具体尾款时间**已到** | **尾款中** |
| 预约已结束 | 其余情况 | 预约已结束 |
| 尾款中 / 现货 | — | 原样返回（**运营声明最优先，时间不改写它**） |

两条不变式：
1. **自动流转只会向后走**：预约中 → 预约已结束 → 尾款中，永不回退；
2. **只有「具体」尾款时间能驱动流转**：大致时间是人的描述，不是确定时刻
   （与既有「缺依据就不猜」口径一致）。

### 3.3 尾款中的出口

**只由运营声明退出**（改成「现货」）。理由是数据里没有「尾款是否收齐」的可判定依据——
硬造一个（例如「尾款任务清零」）会把「有笔尾款还没记」误判成「收齐了」。
`balancePhaseExitsByDeclarationOnly` 把这条口径显式写进代码。

### 3.4 与既有机制的关系（不变量）

- **读取时判定，不做定时任务回写**：真相来源只有「声明 + 预约结束时间 + 尾款时间 + 当前时间」，
  不覆盖运营声明、不需要后台调度、不会出现「存储说预约中、展示说已结束」；
- **不剥夺能力**：尾款中同样提供「预约价全款预约」选项，两选项同屏可选、不隐藏不置灰
  （2026-09-23 用户裁定继续成立）；
- **数据保留**：任何阶段切换都不清空、不隐藏预约价 / 定金 / 尾款 / 现货价。

## 4. 尾款时间（需求四）

### 4.1 存储方式

`CatalogSeries` 上三个 **Optional** 字段，两种粒度**分开存**：

| 字段 | 含义 |
|---|---|
| `balanceDueKind` | `approximate`（大致）/ `exact`（具体）/ `nil`（未填写，等于不启用） |
| `balanceDueText` | **只**承载大致时间的原文（如「大货到后 1 个月」），**故意不解析成日期** |
| `balanceDueAt` | **只**承载具体时刻，且是唯一允许驱动自动流转的字段 |

**切换粒度即清空另一种**：两个字段同时有值时，界面必须替用户挑一个说，一定会说错。
「未填写」是显式选项 → 提供「撤回已填尾款时间」的路径。
切到别的阶段**不清除**（与 `reservationEndAt` 同口径：事实保留，表单只是隐藏）。

### 4.2 校验规则

| 输入 | 规则 |
|---|---|
| 未填写 | 通过（**非必填**；也是清空路径） |
| 大致时间 | 原文非空、≤ 30 字；**不做日期解析** |
| 具体时间 | 必须**严格晚于**预约结束时间（预约结束时间已填时）；早于当前时间**不拦**——那表示尾款已开始收，读完即流转为尾款中 |
| 预约结束时间未填 | 不做比对（没有基准就不猜） |

非法输入**不落库**：红字留在输入框下方；批次详情页保存时同一份判定会拦住保存并给 alert
（判定只有一份，不做两套）。

### 4.3 联动逻辑

| 环节 | 联动 |
|---|---|
| 阶段选择 | 只有「预约中」（需求原文）与「尾款中」（到点后修正实际安排）显示尾款时间输入项 |
| 自动流转 | 具体时间到点 → 生效阶段显示「尾款中」（读取时判定，不改声明值） |
| 表单提示 | 若按当前填写保存后生效阶段会与所选不同，橙色提示写明会变成什么 |
| 商品详情页 | 预约中 / 预约已结束 / 尾款中的加购说明追加「尾款时间：…」；尾款中标签直接显示 |
| 运营列表 | 系列行展示「尾款时间：…」，尾款中系列用琥珀色徽标 |
| 未填 | 任何位置都不渲染尾款时间行（不会出现「尾款时间：—」这类空占位） |

## 5. UI：明确的「同系列共用」提示（需求二）

分两层，落在 `ShopCatalogSeriesConfigSections` 里（两个入口共用，提示不会一边有一边没）：

1. **徽标（常驻）**：三个区块标题右侧各有胶囊徽标「同系列共用」——用户不必展开说明就知道
   这不是单品字段；
2. **范围说明（footer 首行）**：写清共用范围与影响面。批次详情页会给出具体数字
   （「本批次 6 条单品、该系列 12 个商品」），系列编辑页给通用说明。
   另有一句显式影响提示：改动**立即对已发布的同系列商品详情页生效**。
3. 保存按钮下方再复述一次：保存即写回系列实体，不需要逐条单品再改一次。

## 6. 兼容与取舍

- **旧数据零迁移**：新增字段全 Optional；`salePhase == nil` 的系列行为与改动前完全一致；
  旧签名的 `effectivePhase(declared:reservationEndAt:now:)` / `hasAutoFlowed(...)` 保留（等价于「没有尾款时间」）。
- **系列编辑页保留入口**：三项配置仍在系列编辑页可改，但改为**消费同一份组件**。
  保留的理由：存量系列可能没有活跃批次，删掉入口会让封面 / 简介 / 价格表无处可改。
  两边写的是同一份 `CatalogSeries`，且 `apply(to:)` **只写自己负责的字段**，
  不会互相覆盖（名称 / 年月 / 季节归系列编辑页）。
- **尾款中不塌缩成预约已结束**：`ShopCatalogPurchasePhase` 新增独立枚举值，
  否则默认选中会从「定金 + 尾款」变成「预约价全款」，与业务动作不符。
