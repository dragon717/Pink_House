## 1. 版本定位

**一句话**：Android 原生版本，面向国内安卓渠道，同时兼容 HarmonyOS 3/4（运行 Android APK 的鸿蒙设备）。**无后端、无 AI、无云同步**。

### 1.1 兼容目标
- **最低支持**：Android 8.0（API 26）—— 覆盖 HarmonyOS 3/4 底层（AOSP 兼容层）
- **Target SDK**：Android 14（API 34）
- **Compile SDK**：Android 15（API 35）
- **测试重点设备**：
  - 纯安卓：小米、OPPO、vivo、三星主流机型
  - 鸿蒙 3/4：华为 P50 / Mate50 / Nova 11 等（运行 Android APK 模式）

### 1.2 不兼容目标
- 不兼容鸿蒙 Next 5.0（鸿蒙 Next 是独立 HAP 包，见 `harmony_next/PRD.md`）
- 不支持 Android 7.x 及以下（市场份额已不足 2%）

### 1.3 发行渠道
首发渠道：华为 AppGallery、小米应用商店、OPPO 软件商店、vivo 应用商店、应用宝、酷安。**暂不上 Google Play**（国区用户为主）。

## 2. 目标用户

同 iOS 版，但补充以下画像偏移：
- 国内安卓用户支付习惯偏向微信/支付宝
- 相对 iOS 用户客单价略低（需设计更多低门槛入口）
- 部分用户来自 iOS 换机（需保证**跨端迁移路径顺滑**）

## 4. 详细功能规格

> 本节按"功能 ID · 功能名 · 用户故事 · 核心字段 · 边界条件 · 降级/差异说明"的格式展开重点模块。非重点模块（如签到、日历、拼豆）规格详见 `ACCEPTANCE_TESTS.md`。

### 4.1 F-01 ~ F-06 衣橱核心

**F-01 衣橱列表**
- 用户故事：作为用户，我希望快速浏览所有衣物并一眼看到关键信息
- 视图模式：卡片网格（默认，2 列） / 纵向列表
- 卡片显示字段：封面图、名称、品牌、价格、状态标签
- 性能要求：**1000 件衣物列表滚动 60fps，首屏加载 < 500ms**
- 空态：显示引导图 + "添加第一件衣物" CTA

**F-02 衣物新增**
- 入口：底部 Tab "衣橱" → 右上角 "+" / 空态 CTA
- 必填校验：名称、类别
- 图片来源：系统相册 / 拍照 / 默认占位图
- 图片处理：压缩到最长边 1080px、JPEG 质量 85，存入 App 私有目录
- 单件录入平均耗时目标：< 60 秒
- **批量导入**：支持多选相册图片（最多 20 张），每张生成一条记录，标题默认为"未命名-N"，用户后续补全

**F-05 多维筛选**
- 筛选维度：品牌（多选）、类别（多选）、颜色（多选）、价格区间（滑块）、购买日期范围、标签（多选 AND/OR 可切换）、状态（预订/已到手/出售）
- 交互：底部弹出 Sheet，实时预览结果计数，"应用筛选"后跳回列表
- 筛选条件持久化：用户离开页面再回来保留上次筛选（基于 `DataStore`）

### 4.2 F-11 ~ F-20 宠物互动

**F-18 拖拽衣物给宠物（非 AI 降级）**
- iOS 版行为：调用 Qwen-VL 分析衣物图片，生成个性化评价
- **Android 版行为**：
  1. 用户从衣橱列表拖拽衣物到宠物页
  2. 系统检测到拖拽完成，根据衣物的 **类别 + 主色调 + 价格档位** 查**预设文案矩阵**
  3. 文案矩阵示例：
     - `{类别=裙, 颜色=粉, 价格=高}` → 池子有 5 条文案随机抽 1，如"这条粉色裙子好梦幻呀~主人穿上一定像公主!"
     - `{类别=鞋, 颜色=黑, 价格=中}` → 池子有 5 条文案，如"黑色的鞋子百搭又显瘦呢~"
  4. 气泡弹出时长 4 秒，同时宠物播放"开心"动画
- 文案矩阵规模：至少覆盖 **5 类别 × 8 色系 × 3 价格档位 = 120 组合**，每组合 5 条，共 **600+ 条文案**

**F-19 宠物聊天页**
- iOS 版行为：用户输入 → LLM 生成回复（VIP）/ TTS 变声复述（非 VIP）
- **Android 版行为**：
  1. 聊天页 UI 完整保留（输入框、发送按钮、气泡列表）
  2. 用户发送消息 → **立即弹兜底回复**（从兜底文案池随机抽 1）：
     - "听不懂呢...主人在说什么呀?"
     - "咦?这个词好像没听过耶~"
     - "(歪头) 主人再说一遍?"
     - "(摇尾巴) 我好像听不太明白..."
     - 至少 10 条兜底文案
  3. 用户消息仍正常入库，保留历史气泡
  4. 聊天页**不显示 "VIP 解锁智能对话" 入口**（无 AI 就别诱导消费）

**F-20 规则式气泡（完整保留 iOS 逻辑）**
- 触发源：喂食、饮水、打工开始/结束、抚摸、状态变化（饱食度/心情跨阈值）、时段问候（早安/午安/晚安）、节日问候（春节/中秋等）
- 每个触发源维护至少 5 条预设文案，随机抽取
- 同一触发源连续两次不抽到相同文案（防重复）
- 文案池从 iOS `PetChatGuidanceEngine` 等源代码抽取 → 迁移为 Android 的 `strings.xml` 字符串数组资源

### 4.3 F-30 ~ F-35 VIP 与充值

**核心模型**（与 iOS 一致）：
```
微信/支付宝支付 → 喵币到账 → 花喵币买 VIP → 解锁两个商店的折扣
```
**VIP 不是直接用人民币购买的商品**，必须通过喵币流转。

**F-32 VIP 中心页**
- 卡片区：VIP 卡片 + 用户 VIP 编号（非 VIP 时显示"尊贵身份待解锁"）
- 到期时间（VIP 时显示）
- 权益区（列表，**完全复用 iOS 文案**）：
  - ✅ 宠物商店享 -40% OFF（零食/玩具等）
  - ✅ 主题皮肤商店享 -10% OFF
  - ✅ VIP 专属尊贵编号（6-8 位幸运数字）
  - ✅ VIP 卡片高级皮肤（monicaPink 等）
- 开通按钮：下方常驻"立即开通"，点击进入套餐选择
- 未 VIP 且从未试用过的用户：首次进入 VIP 中心可看到"3 天免费试用"按钮
- **Android 版本隐藏**：智能对话权益、App Icon 切换权益（根本不展示不提及）

**F-33 喵币充值（6 档）**
- 档位与赠送（与 iOS 完全一致，见下表）：

| 档位 | 价格 | 基础喵币 | 赠送 | 首充双倍 | 标识 |
|---|---|---|---|---|---|
| `meowcoin_60` | ¥6 | 60 | +6（10%） | 首次 120 | — |
| `meowcoin_120` | ¥12 | 120 | +12（10%） | 首次 240 | — |
| `meowcoin_300` | ¥30 | 300 | +30（10%） | 首次 600 | — |
| `meowcoin_500` | ¥50 | 500 | +75（15%） | 首次 1000 | 热门 |
| `mcoin_1280` | ¥128 | 1280 | +320（25%） | 首次 2560 | 最划算 |
| `mcoin_3280` | ¥328 | 3280 | +1148（35%） | 首次 6560 | — |

- **首充双倍每档独立**：买完 ¥6 档不影响 ¥12 档的首充权益
- **支付方式**：微信支付 + 支付宝（并列展示，用户选择）
- **流程**：
  1. 用户选档 → 选支付方式 → 跳起微信/支付宝 App
  2. 支付完成 → 回调本 App → 显示结果页（成功/失败）
  3. 本地订单表持久化 `{orderId, channel, productId, coinAmount, status, timestamp, firstDoubleApplied}`
  4. **幂等**：同一 orderId 已处理，不重复加币（用户可放心重试）
- **失败处理**：显示"支付失败，可重试"+ 查单按钮（调支付宝/微信查单 API 确认订单状态，防止"实际扣款但本 App 没发币"）

**F-34 VIP 开通（喵币支付）**
- 套餐（与 iOS 一致）：
  - 月卡：66 喵币
  - 季卡：188 喵币（-5% OFF 标识，相对 66×3=198）
- 用户点击开通 → 检查喵币余额 → 扣币 → 激活/续期 VIP
- VIP 有效期本地持久化；已是 VIP 再次购买 → 在现有到期日上**叠加**月数
- 到期前 3 天本地通知提醒续费

**F-54 VIP 3 天试用**
- 条件：`trialUsed == false` 且当前非 VIP
- 流程：点击"开始试用" → 二次确认 → `trialUsed = true` + `trialStartDate = now` + `trialExpireDate = now + 3d` + VIP 激活
- 试用到期后自动降级为普通用户，不自动续费
- **每用户终身一次**

### 4.4 F-36 ~ F-38 通知

**F-36 通知中心页**
- 数据源：本地数据库表 `local_notification`，字段 `{id, type, title, body, triggerTime, readAt, payload}`
- UI：按时间倒序列表，未读小红点
- 空态："还没有提醒哦~"

**F-37 本地提醒**
- 触发条件：
  - 尾款：衣物有尾款且 `remainingPaymentDate` 在 T-3 / T-1 / T 日提醒一次
  - 签到：每日 9:00 或用户配置时间（非严格精确，允许 5 分钟漂移）
  - 宠物饥饿：饱食度 ≤ 20% 且 App 最近 24h 未开启过，弹一次
- 实现：
  - 前台：Foreground Service 监听 / 启动时检查
  - 后台：`AlarmManager.setExactAndAllowWhileIdle` + `BroadcastReceiver` + 开机自启 `RECEIVE_BOOT_COMPLETED`
- 通知渠道（Android 8+ 必须）：
  - `channel_deposit` - 尾款提醒（高优先级）
  - `channel_checkin` - 签到提醒（低优先级）
  - `channel_pet` - 宠物状态（低优先级）

## 5. 非功能需求

### 5.1 性能
- 冷启动 < 2.5 秒（中端机如 Redmi Note 12）
- 衣橱列表 1000 件滚动不掉帧（60fps）
- 内存峰值 < 300MB（正常使用）
- 包体积 < 80MB（MVP 阶段）

### 5.2 设备兼容
- 屏幕适配：5.0" ~ 7.0" 手机（折叠屏暂不专门适配，v1.1 再考虑）
- 平板：一期仅确保不崩，不单独做大屏布局
- HarmonyOS 3/4 兼容：走 AOSP 兼容层，**禁止使用**只在 GMS 上可用的 API（Google Play Services、Firebase 等）
- 深色模式：跟随系统

### 5.3 权限
- 必选：存储（Scoped Storage）、相机、通知
- 可选：相册访问、震动、精准闹钟（`SCHEDULE_EXACT_ALARM`，Android 12+）
- **不申请**：位置、联系人、麦克风、蓝牙、电话状态

### 5.4 隐私与合规
- 启动时必须出示**隐私政策 + 用户协议同意弹窗**（国内合规）
- **个人信息收集清单**明示（应用市场要求）
- 不上报任何设备 ID、IMEI、MAC 到服务器（本就无服务器）
- 支持账号注销（本地数据清空）

### 5.5 可观测性
- 内置 Logger（复用 iOS 的 `Logger.swift` 思想，Android 用 Timber）
- 崩溃收集：Bugly 或 Sentry（可选）
- **不接**统计埋点（无后端无法上报，可选本地埋点用于 debug）

## 6. 数据迁移

### 6.1 从 iOS 迁移到 Android
用户操作流程：
1. iOS 端：设置 → 数据管理 → 导出备份 → 生成 `pinkhouse_backup_yyyymmdd.json`
2. 通过微信/邮件/AirDrop 把 JSON 文件传到 Android 手机
3. Android 端：设置 → 数据管理 → 导入备份 → 选文件 → 解析
4. 解析时：
   - 识别版本号 3.0 → 忽略裙子股市、CloudKit 相关字段
   - 识别版本号 3.0-lite → 全部字段导入
   - 其他版本号 → 弹错"不支持的备份版本"
5. 图片字段：v1.0 不迁移（显示占位图 + 提示"图片需要重新上传"），v1.1 考虑 zip 打包

### 6.2 Android 之间迁移
同路径，JSON 版本标 `3.0-lite`。
