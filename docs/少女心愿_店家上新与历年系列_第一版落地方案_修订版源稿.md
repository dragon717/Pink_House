## 0. 封面

- 标题：少女心愿 · 店家上新 / 历年系列 · 第一版落地方案
- 副题：商品档案 × 少女衣橱 × 心愿尾款 × 运营快捷录入
- 版本：V1.1（修订版）｜第一版范围确认
- 引言：“不是商城，而是少女心愿自己的 Lolita 店家商品档案库。”
- 说明：普通用户只看资料、加入心愿 / 少女衣橱；白名单运营负责补录与维护。运营端淘宝快捷导入纳入 P0。

## 1. 一页结论

| 确认项 | 第一版结论 |
|---|---|
| 产品定位 | 做店家当前上新与历年系列的商品档案，不做商城、不提供任何购买链接。 |
| 用户端 | 从「时光馆」进入店家上新：查看店家 → 系列 → 商品 → 图片 / 配色 / 尺码 / 尺码表 / 预约价 / 现货价，并可加入心愿、少女衣橱；预约商品可进入心愿尾款。 |
| 尾款边界 | 只保留「已付定金 → 待付尾款 → 尾款完成 → 加入少女衣橱」，没有已发货、已收货。 |
| 价格模型 | 预约价和现货价必须并存，不能覆盖；同一商品允许多次预约 / 现货 / 再贩记录。 |
| 运营端 | 白名单运营可从淘宝链接或分享文本一键尝试拆分，自动生成草稿；拆不出的字段继续手工补录。运营入口：设置 → 运营工具 → 店家商品库。 |
| 第一版重点 | 手机端完成全流程，不依赖 PC；自动解析是加速器，不是发布前置条件。 |

## 2. 产品边界

### 2.1 做什么

- 店家当前上新
- 店家往年系列 / 品牌年鉴
- 系列下所有款式
- 商品图片、配色、尺码、尺码表
- 历史预约价、当前现货价及差价
- 加入心愿
- 加入少女衣橱
- 预约商品进入心愿尾款
- 运营白名单补录与修正
- 运营淘宝内容快捷导入

### 2.2 明确不做

- 任何用户侧购买链接 / 淘宝跳转
- 商城、支付、订单
- 物流、已发货、已收货
- 普通用户修改公共商品资料
- 第一版开放 UGC 商品投稿
- 淘宝解析结果自动发布

## 3. 核心业务架构

```text
Shop 店家
  ↓
Series 系列
  ↓
Product 商品
  ├─ ProductVariant 配色 / 尺码
  ├─ SizeChart 尺码表
  ├─ CatalogAsset 图片资源（含 originalURL）
  └─ SaleEvent[] 销售历史
        ├─ reservation 预约价
        ├─ stock 现货价
        └─ rerelease 再贩
```

公共商品事实与用户私有状态分离：

- 公共 Catalog → 这件商品「是什么、什么时候卖过、多少钱」
- 用户状态 → 我「想要 / 已预约 / 已拥有」

## 4. 用户端流程与页面

### 4.1 完整用户流程

```text
时光馆 → 店家上新 → 店家列表 → 店家主页 → 当前上新 / 历年系列
→ 系列详情 → 商品详情
→ [加入心愿] / [我已经预约] / [加入少女衣橱]
```

> V1.1 修订：入口由 V1.0 的「首页」统一为「时光馆」（现有底部导航第 3 个 Tab），不新增 Bottom Tab。

| 页面 | 第一版展示重点 |
|---|---|
| 店家上新首页 | 搜索店家名称与别名（系列 / 款式搜索列入后续迭代）；当前上新、最近上新、历年系列、全部店家；主卡片以「系列」为单位。 |
| 店家主页 | 店家封面 + 当前上新 + 按年份查看历年系列，形成品牌年鉴。 |
| 系列详情 | 系列主视觉、年份 / 季节、系列下全部商品，支持分类筛选（全部 / JSK / OP / SK / Blouse / KC / 小物 / 鞋 / 包 / 其他）。 |
| 商品详情 | 商品图、配色、尺码、尺码表、价格档案，以及用户操作按钮。 |
| 心愿 | 代表「我想拥有」，从 Catalog 引用商品资料，用户只补自己的选择 / 备注。 |
| 心愿尾款 | 代表「我已经预约」，记录总价、定金、待付尾款、尾款时间与提醒。 |
| 少女衣橱 | 代表「我已经拥有」，自动带入店家、系列、商品图、尺码表等公共资料。 |

## 6. 价格档案模型

预约价和现货价不是同一个字段的「新旧值」，而是同一商品的不同 SaleEvent。

用户端示例：

```text
价格档案
历史预约  ¥428
当前现货  ¥568
比预约价高 ¥140（+32.7%）
```

| 记录 | 类型 | 价格 | 时间 | 展示 |
|---|---|---|---|---|
| SaleEvent #1 | reservation | ¥428 | 2026.09 | 历史预约价 |
| SaleEvent #2 | stock | ¥568 | 2026.11 | 当前现货价 |
| SaleEvent #3 | rerelease | 可选 | 未来 | 后续自然扩展 |

> V1.1 修订：示例时间由 V1.0 的 2025.11 / 2026.01 统一为 2026.09 / 2026.11，与《第一版落地计划》一致。

## 9. 第一版 P0：淘宝链接 / 分享文本快捷导入

结论：手机端能做，并正式纳入第一版。

产品定义：能解析多少就自动填多少，剩余字段由运营补录；解析永远只生成 Draft，不直接发布。

### 9.1 输入

- 淘宝商品 URL
- 淘宝完整分享文本（优先推荐）

### 9.2 第一版尽量识别字段

- 淘宝 URL / 商品标识
- 店家名称候选
- 商品标题
- 系列名称候选
- 商品类型（JSK/OP/SK…）
- 商品图片（可访问时）
- 颜色
- 尺码
- 预约价 / 现货价 / 定金 / 尾款
- 预约开始 / 结束时间

尺码表第一版不强求自动 OCR：能拿到原图就先保存原图，结构化尺码由运营补录。

### 9.3 解析结果状态

| UI 状态 | 含义 | 后续动作 |
|---|---|---|
| ✓ 已识别 | 高置信度字段 | 运营快速确认 |
| ? 请确认 | 自动识别但不确定 | 运营选择或修正 |
| 待补充 | 未识别 | 手工填写 |

### 9.4 失败兜底

禁止把「无法完整抓取淘宝页面」设计成流程失败。

```text
成功解析 7 项 + 缺失 3 项
→ 显示「已整理出部分资料」
→ 继续手动补录
→ 保存草稿
```

## 10. 自动匹配与防重复

- 已有店家匹配：根据店家名 / aliases 匹配，避免同一个品牌重复创建。
- 已有系列匹配：解析到「雪国来信 JSK」时，优先提示当前店家已有「雪国来信」系列。
- 已有商品匹配：发现同名同系列商品时，优先打开已有 Product，而不是创建第二条。
- 预约 → 现货追加：新淘宝内容如果只是同一商品的现货销售，推荐新增 stock SaleEvent。

```text
复制新现货淘宝内容
→ 识别「雪国来信 JSK」
→ 发现已有 Product
→ 本次识别现货 ¥568
→ [添加为现货记录]
→ 原预约 ¥428 继续保留
```

> V1.1 修订：关键测试故事演示数据统一为店家 Alice Girl、系列「雪国来信」（与《第一版落地计划》§35 同一套数据；UNNIQ 仅作别名搜索示例）。

## 11. 数据模型

| 模型 | 核心字段 |
|---|---|
| Shop | id, name, aliases, logo, cover, description |
| Series | id, shopID, name, year, season, cover, description |
| Product | id, shopID, seriesID, name, category, images, description |
| ProductVariant | id, productID, color, size |
| SizeChart | productID, columns, rows, sourceImage |
| SaleEvent | id, productID, type, price, deposit, balance, startAt, endAt |
| CatalogAsset | id, type, thumbnailURL, previewURL, originalURL, width, height |

> V1.1 修订：补充 V1.0 缺失的 CatalogAsset，与《第一版落地计划》Catalog 数据模型一致。

现有用户模型不重写，只增加可选引用字段：

```text
Wishlist / TailPayment / Wardrobe
+ catalogProductID?
+ catalogVariantID?
+ saleEventID?
```

少女衣橱条目模型（WardrobeEntry = primaryItem + accessories[]）的完整字段定义见《第一版落地计划》第二部分。

## 14. MVP 验收标准

（与《第一版落地计划》§37 一致，完整清单见该文档。）

- 用户端：查看上新与历年系列；查看图片 / 配色 / 尺码 / 尺码表；同时看到预约价与现货价；加入心愿；加入少女衣橱。
- 尾款：有已付定金 / 待付尾款 / 尾款完成；没有已发货 / 已收货。
- 运营：白名单可见运营入口；可手动创建 / 补充店家、系列、商品、尺码表、价格；可保存草稿并审核发布。
- 淘宝快捷导入：支持 URL 与分享文本；至少生成部分字段草稿；缺失字段可继续补录；部分解析失败不阻塞；能匹配已有商品并追加 stock SaleEvent；淘宝链接不展示给普通用户。

## 15. 第一轮实践建议

不要先追求数据量，先验证模型是否自然。

- 3 个店家；每家 3～5 个系列；每系列 3～6 个商品
- 覆盖 JSK / OP / SK / KC
- 覆盖仅预约、预约后现货、仅现货、历史系列
- 准备 3 类淘宝样本：能解析 / 部分解析 / 几乎无法解析

关键测试故事：

```text
运营复制淘宝分享文本
→ 自动识别 Alice Girl / 雪国来信 JSK / 预约 ¥428
→ 手动补尺码表
→ 发布
→ 用户加入心愿或少女衣橱
→ 数月后运营再次导入现货信息 ¥568
→ 系统匹配已有商品并追加 stock SaleEvent
→ 用户端同时看到预约 ¥428 与现货 ¥568
```

## 16. 开发约束（必须遵守）

约束清单以《第一版落地计划》§34 合并版为准（18 条，两份文档共用同一编号）。要点：

1. 不为新功能重写现有衣橱 / 心愿 / 尾款。
2. Series 和 Product 不合并。
3. 预约价与现货价不覆盖，全部保留历史。
4. 商品名称不能作为稳定 ID。
5. 公共 Catalog 实体优先归档，不物理删除已被用户引用的数据。
6. 淘宝解析只生成 Draft，不自动发布。
7. 淘宝快捷导入是效率工具，手动录入始终可完整完成。
8. 用户侧绝不展示购买链接。

## 17. 最终定义

第一版建设的不是「商城上新页」，而是少女心愿自己的 Lolita 店家商品档案库 + 手机端高效率运营工具。

自动化能做多少做多少，人工永远可以兜底；淘宝只作为运营侧信息输入来源，不成为用户侧购买入口。
