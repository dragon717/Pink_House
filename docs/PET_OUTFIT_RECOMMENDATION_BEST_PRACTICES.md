# 萌宠智能搭配最佳实践

> 更新时间：2026-04-07  
> 适用范围：`智能搭配`、`+1 / 加一件`、`换一件`、`魔法贴纸`、天气穿衣建议、穿搭延续推荐。

## 1. 文档目标

这份文档用于冻结萌宠穿搭推荐的核心口径，避免后续继续出现这些问题：

- 20 多度仍然推荐冬季大衣或厚秋装。
- `上衣 / 内搭 / 短袖 / 长袖` 被误并进 `外套`。
- `开衫` 的主类、补位能力、展示文案三者不一致。
- AI 描述和本地最终选中的单品不一致。
- `智能搭配`、`+1`、`换一件`、`魔法贴纸` 四条链路规则不统一。

## 2. 冻结分类口径

### 2.1 一级语义分类

- `dress`：JSK、OP、SK、连衣、半裙、吊带裙。
- `top`：上衣、内搭、打底、短袖、长袖、衬衫、背心。
- `outerwear`：外套、开衫、罩衫、披肩、斗篷、薄外套、防晒衫、空调衫。
- `shoes`：玛丽珍、单鞋、凉鞋、靴、皮鞋等。
- `accessory`：发饰、项链、袜子、包、手袖、帽子等。
- `umbrella`：晴雨伞、防晒伞、折叠伞等。
- `other`：无法稳定归类但仍可被候选池使用的单品。

### 2.2 开衫的双重语义

- `开衫` 的主类永远保留在 `outerwear`。
- 但 `开衫` 可以具有 `actsAsTop = true` 的补位能力。
- 这只意味着：当当前造型缺少上身单品时，轻薄开衫可以补 `top` 位。
- 这不意味着：所有开衫都应该在 UI、筛选页、文案里直接显示成“上衣”。

### 2.3 上衣细分

- `inner`：内搭、打底。
- `shortSleeve`：短袖、短 T。
- `longSleeve`：长袖、长 T。
- `shirt`：衬衫、blouse、shirt。

上衣细分主要服务于三件事：

- 温度判断。
- 文案展示。
- `+1 / 换一件` 时的优先补位。

## 3. 推荐链路统一原则

所有与穿搭相关的功能都应共用同一套语义和约束，而不是各自写一份局部规则。

### 3.1 四条核心链路

1. `智能搭配`：从候选集中组合出 2-4 件。
2. `+1 / 加一件`：在当前造型上补一个缺口。
3. `换一件`：围绕指定或默认槽位做替换。
4. `魔法贴纸`：展示的推荐结果必须与当前最终选中的单品一致。

### 3.2 必守一致性

- 同一套分类语义必须贯穿：意图识别、候选召回、排序、后处理、展示文案。
- AI 负责给出方向与描述，本地负责最终筛选和兜底。
- 一旦本地对 AI 候选进行了重排或替换，摘要文案必须基于“最终单品”重建，不能继续沿用旧描述。

## 4. 温度与穿衣指南

默认看 `体感温度 feelsLikeTemperature`，而不是日历季节。

| 体感温度 | 推荐重点 | 默认限制 |
|---|---|---|
| `0-10°C` | 重外套、厚针织、强保暖层 | 可正常推荐保暖外套 |
| `11-15°C` | 轻呢、针织、薄毛衣、轻外套 | 重外套开始收缩 |
| `16-20°C` | 长袖、衬衫、内搭、轻薄开衫 | 厚外套明显降权 |
| `21-25°C` | 上衣优先：内搭、短袖、长袖、衬衫；外套仅轻薄开衫/防晒衫/空调衫 | 不推荐厚秋装、大衣、毛呢、棉服、羽绒 |
| `26-30°C` | 短袖、轻薄透气材质 | 外套仅在防晒、空调房、雨天场景出现 |
| `30°C+` | 极轻薄、透气、吸汗 | 默认不推荐常规外套 |

### 4.1 已冻结的温度规则

- `20°C+`：屏蔽厚重大衣、毛呢、棉服、羽绒等重外搭。
- `23°C+`：若用户未明确提出保暖或外套诉求，不把常规厚秋装外套作为默认推荐。
- `23°C` 左右默认优先推荐：
  - `top`：内搭、短袖、长袖、衬衫
  - `outerwear`：轻薄开衫、防晒衫、空调衫

### 4.2 需要额外考虑的天气维度

- 降雨：鞋履防水性、伞具可用性。
- 大风：披肩类、轻薄罩衫可适度降权。
- 强日晒：防晒衫、轻薄罩衫可升权。
- 空调房：轻薄开衫比厚外套更合理。

## 5. 配色最佳实践

### 5.1 默认优先级

1. 同色系：最稳妥。
2. 邻近色：次优，视觉柔和。
3. 互补色点缀：仅适合小面积，不适合两件大件硬撞。

### 5.2 主色控制规则

- 一套造型主色建议 `1-2` 个。
- 非中性色总数建议不超过 `2` 个。
- 鞋包和小物优先承担中和与收口作用。

### 5.3 百搭颜色

适合作为鞋、包、袜、小物、过渡外搭默认优先色：

- 白
- 奶油白 / 米白
- 米色 / 杏色
- 灰
- 黑
- 棕 / 咖 / 驼
- 海军蓝
- 丹宁蓝

## 6. 智能推荐涉及的核心要素

### 6.1 用户输入要素

- 意图：智能搭配、加一件、换一件、查天气、找上衣、找外套。
- 明确品类：主裙、上衣、内搭、短袖、长袖、衬衫、开衫、外套、鞋、小物、伞。
- 明确颜色：浅色、粉色系、蓝色系、中性色等。
- 明确温度或天气诉求：热、冷、下雨、风大、防晒、空调房。
- 明确风格和场景：通勤、日常、甜系、古典、约会、出游。

### 6.2 衣橱数据要素

- 类别与类型词。
- 颜色与色系。
- 材质。
- 衣长。
- 保暖等级。
- 防雨等级。
- 适用季节。
- 是否已到手、是否可穿。
- 创建时间或最近使用情况。

### 6.3 造型上下文要素

- 当前已经选中的主裙。
- 当前是否已有 `top`。
- 当前是否已有 `outerwear`。
- 当前色系是否已经过多。
- 当前是否已经有过多大件。

## 7. 推荐排序最佳实践

### 7.1 候选池阶段

- 先按意图筛出最相关的语义池。
- `top` 和 `outerwear` 必须独立建池，不允许一开始就混成一个大池。
- 如果用户明确说“找上衣”，上衣池优先。
- 如果用户明确说“找外套”，外套池优先。

### 7.2 评分阶段

综合考虑以下因素：

1. 用户明确品类是否命中。
2. 当前天气是否允许该单品出现。
3. 单品是否能填补当前造型缺口。
4. 颜色是否与主裙或当前造型同色系/邻近色。
5. 该单品是否会把主色数推高到不稳定区间。
6. 是否属于当前场景更合适的轻量单品。

### 7.3 后处理阶段

- `top` 必须保留独立槽位，不能在最终重排时再并回 `outerwear`。
- 一套里允许同时存在 `top + outerwear`。
- `+1` 默认优先补：
  1. `top`
  2. `accessory`
  3. `shoes`
  4. `outerwear`

### 7.4 文案阶段

- 用最终选中的单品重建摘要。
- 当命中上衣诉求时，文案优先用 `内搭 / 短袖 / 长袖 / 衬衫 / 上衣`。
- 当命中轻薄开衫诉求时，再用 `开衫 / 外套 / 罩衫`。
- 避免出现“推荐的是上衣，文案却说外套”这类割裂感。

## 8. 魔法贴纸与快捷引导最佳实践

### 8.1 快捷引导

当前造型缺什么，快捷选项就优先补什么：

- 缺上衣：`加一件上衣`
- 有上衣缺外搭：`加一件轻薄开衫`
- 上身完整：`换个浅色小物`

### 8.2 魔法贴纸

- 贴纸展示的推荐结果，必须来自当前最终筛选后的单品。
- 不能直接展示 AI 的原始描述而忽略本地后处理结果。
- 若本地发生了替换、补位、重排，贴纸摘要也必须同步重建。

## 10. 常见错误清单

- 把 `上衣 / 内搭 / 衬衫` 继续映射到 `outerwear`。
- 在高温场景继续推荐厚外套，只因为它季节标签写了“春秋”。
- `开衫` 被当成“既是上衣又是外套”，最终展示时重复占位。
- 本地筛掉了厚外套，但文案还在夸“秋冬层次感”。
- OOTD 分类已经拆开，但筛选页又把 `shirt/top` 救援进外套页。

## 11. 测试与 Review 清单

### 11.1 温度用例

- `23°C`：默认不应出现大衣、毛呢、羽绒、棉服。
- `23°C + 明确要开衫`：允许轻薄开衫，不允许厚针织大衣。
- `28°C`：优先短袖、内搭、轻薄材质。
- `12°C`：允许外套权重明显提升。

### 11.2 分类用例

- `加一件上衣`：优先上衣，不应只返回外套。
- `加一件轻薄开衫`：优先轻外搭。
- `换上衣`：默认替换 `top` 槽位。
- `找外套`：候选池不应混入短袖、长袖、衬衫。

### 11.3 一致性用例

- AI 文案与最终单品列表是否一致。
- 魔法贴纸展示是否与最终推荐一致。
- 快捷引导按钮是否和当前造型缺口一致。

## 13. 结论

萌宠智能搭配不是单纯“让模型随便选几件衣服”，而是一条由以下模块组成的联合决策链：

- 用户意图理解
- 衣橱语义建模
- 温度与天气约束
- 色彩和谐控制
- 上下文补位策略
- 本地后处理与兜底
- 文案与 UI 一致性

后续如果要继续扩能力，例如“按场景搭配”“一键通勤版”“旅行打包推荐”，应继续复用这条链，而不是绕开它另起一套临时规则。
