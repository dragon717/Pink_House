# 少女衣橱主题皮肤重构方案

更新时间：2026-04-17

## 当前落地状态（2026-04-17）

已落地的能力：

- 新增独立主题皮肤链路：`ThemeSkinManager`、`ThemeSkinProduct`、`ThemeSkinDescriptor`、主题购买/启用/slot 开关持久化。
- “我”页已拆分“主题”和“主题配色”两个入口，主题入口进入独立 `ThemeSkinStoreView`。
- 已完成第一期主题壳接线：
  - 顶部栏主容器 / 分段 / 图标按钮：`HomeView` + `HomeThemeSkinComponents`
  - 底部栏主容器 / Tab item：`MainTabView` + `TabBarThemeSkinComponents`
  - 衣橱统计卡 / 商品卡：`WardrobeView`、`ClothingCard` + `WardrobeThemeSkinComponents`
  - “我”页设置豆腐块卡片：`SettingsGridItem`
- 主题详情页的组件开关已补齐本期真实接线的 slot：`topBarMain`、`topBarSegment`、`topBarIconButton`、`searchBar`、`statsCard`、`wardrobeItemCard`、`tabBarMain`、`tabBarItem`。

本期仍保留到下一阶段的能力：

- `topBarAddButton` 独立商品化支持仍是预留，当前通过 `topBarIconButton` 视觉回退。
- `filterSheet`、`emptyState`、`GlobalSearch` 结果行等更细粒度皮肤化还未接线。
- 原生 `.searchable` 仍保留系统交互，仅外围入口和承托层做主题化，不做完全自绘搜索控件。

## 1. 目标

基于参考稿 `temp/主题-旋转木马/少女衣橱.png`，为 Pink House 落地一套“主题皮肤包”能力。此次不是单纯换配色，而是对以下原生/半原生 UI 容器做主题化替换：

- 顶部栏
- 底部 TabBar
- 顶部操作按钮
- 搜索栏
- 分段/筛选控件
- 卡片体系
- 相关徽标、提示胶囊、空态容器

同时满足以下业务规则：

- 入口在“我”页的“主题”部分，不放在“配色”部分。
- 主题按单套商品售卖，单价 `99` 喵币，VIP 享 `9` 折，即 `89` 喵币。
- 购买后只能使用该主题自己的组件集。
- 用户可以对该主题内部组件逐个启用/停用。
- 不允许不同主题之间混用组件。

## 2. 当前现状结论

### 2.1 已有的是“配色系统”，不是“组件皮肤系统”

项目已经有成熟的主题配色基础设施：

- `ThemeManager` 负责背景、卡片样式、配色模式、主题配置持久化。见 `ItemManager/Services/ThemeManager.swift:54`
- `ThemePreset` / `ThemeColorConfig` 负责亮暗两套文字与卡片颜色数据。见 `ItemManager/Utilities/AdaptiveColorSystemV2.swift:84`、`ItemManager/Utilities/AdaptiveColorSystemV2.swift:441`
- `MagicThemeDesignSystem` 已经把颜色映射为语义 palette。见 `ItemManager/Utilities/MagicThemeDesignSystem.swift:31`
- `ThemeManager+MagicThemeSets` 已支持“保存我的主题方案”。见 `ItemManager/Services/ThemeManager+MagicThemeSets.swift:3`

但是它们当前只覆盖：

- 文字颜色
- 卡片背景/强调色
- 导航/分段的语义色
- 背景图/背景色

还没有覆盖：

- 顶部栏布局变体
- TabBar 结构皮肤
- 搜索栏壳体
- 图标按钮壳体
- 商品卡花边/贴纸/挂件式装饰
- 主题资产所有权与组件级启停

### 2.2 当前商业模型与目标规则冲突

现有“主题配色”是功能解锁，不是单主题购买：

- `themeCustomize` 当前默认条件为“累计消费 50 喵币后解锁”。见 `ItemManager/Services/FeatureUnlockManager.swift:243`
- `meowCoin` 类型在解锁时不会再次扣费，只是校验累计消费并领取。见 `ItemManager/Services/FeatureUnlockManager.swift:625`、`ItemManager/Services/FeatureUnlockManager.swift:690`
- `themeCustomize` 还存在 VIP 临时可用桥接。见 `ItemManager/Services/FeatureUnlockManager.swift:583`

这与本次要做的“99 喵币购买单个主题包”完全不同，因此必须拆分：

- “配色”继续走现有 `ThemeManager`
- “主题皮肤包”新增独立购买、持有、启用和渲染链路

### 2.3 项目里已经有一个可复用的“视觉系统先行”样板

VIP 中心这次改造很值得复用方法论：

- 已将视觉 token 抽成 `VIPVisualTheme` / `VIPGlassStyle` / `VIPGlassCardBackground`。见 `ItemManager/Views/VIP/VIPVisualSystem.swift:3`
- 已把折扣角标抽成共享组件 `DiscountBadgeView`。见 `ItemManager/Views/Components/DiscountBadgeView.swift:40`
- 文档明确强调“先抽视觉 token，再映射业务入口”。见 `docs/VIP_UI_PLAYBOOK.md:26`

这套方法应直接复用到主题皮肤商店与少女衣橱主题包体系。

## 3. 入口与业务链路现状

### 3.1 我的页入口

当前“我”页只有一个“主题配色”入口：

- 入口豆腐块在 `MeView` 中，标题为“主题配色”。见 `ItemManager/Views/MeView.swift:173`
- 点击后进入 `MagicColorSettingsView`。见 `ItemManager/Views/MeView.swift:174`

结论：

- 需要把“主题”与“配色”拆成两个入口。
- “主题”负责主题皮肤包商店、已购主题、组件启停。
- “配色”继续保留当前 `MagicColorSettingsView`。

### 3.2 现有配色页结构

当前 `MagicColorSettingsView` 已经区分“魔法配色”和“客制化配色”：

- 页签模式：`magic` / `custom`。见 `ItemManager/Views/Settings/MagicColorSettingsView.swift:153`
- 预览区：`ThemePreviewSection`。见 `ItemManager/Views/Settings/MagicColorSettingsView.swift:66`
- “我的主题方案”模块：`MagicThemeModuleSection`。见 `ItemManager/Views/Settings/MagicColorSettingsView.swift:102`

结论：

- 现有页面不适合直接承载“主题皮肤包购买”。
- 建议新增 `ThemeSkinStoreView`，不要继续向 `MagicColorSettingsView` 塞业务。

### 3.3 喵币与 VIP 折扣现状

商业化基础设施已可复用：

- 商业化文档已明确“喵币可兑换主题”。见 `docs/商业化开发书.md:5`
- 喵币购买页已存在。见 `ItemManager/Views/IAP/MeowCoinStoreView.swift:7`
- VIP 主题皮肤商店折扣文案已存在：`-10% OFF`。见 `ItemManager/Services/VIP/VIPManager.swift:13`
- VIP 中心也已经预留“主题皮肤商店 -10% OFF”。见 `ItemManager/Views/VIP/VIPCenterView.swift:120`

结论：

- 本次不需要重做喵币购买。
- 只需要新增“主题皮肤商品购买逻辑”和“VIP 价计算”。

## 5. 建议的主题组件编码

本次不要继续沿用“按颜色主题命名”的方式，而应建立“主题包 + 组件槽位”编码体系。

### 5.1 主题 ID

建议格式：

`theme_skin.<themeId>`

示例：

- `theme_skin.girl_closet`
- `theme_skin.rococo_boudoir`
- `theme_skin.dream_carousel`

参考稿建议首个主题 ID：

- `theme_skin.girl_closet`

### 5.2 组件槽位编码

建议格式：

`skin.<themeId>.<slot>.<variant>.<state>`

示例：

- `skin.girl_closet.top_bar.main.default`
- `skin.girl_closet.top_bar.segment.selected`
- `skin.girl_closet.top_bar.icon_button.default`
- `skin.girl_closet.search_bar.compact.default`
- `skin.girl_closet.tab_bar.main.default`
- `skin.girl_closet.tab_bar.item.selected`
- `skin.girl_closet.card.stats.default`
- `skin.girl_closet.card.wardrobe_item.default`
- `skin.girl_closet.card.settings_grid.default`
- `skin.girl_closet.button.primary.default`
- `skin.girl_closet.button.icon_circle.default`
- `skin.girl_closet.badge.discount.default`
- `skin.girl_closet.sheet.filter.default`
- `skin.girl_closet.empty_state.search.default`

### 5.3 槽位枚举

建议新增：

```swift
enum ThemeSkinSlot: String, Codable, CaseIterable {
    case topBarMain
    case topBarSegment
    case topBarIconButton
    case topBarAddButton
    case searchBar
    case tabBarMain
    case tabBarItem
    case segmentedControl
    case filterChip
    case statsCard
    case wardrobeItemCard
    case settingsGridCard
    case sectionCard

    case iconCircleButton
    case discountBadge
    case filterSheet
    case emptyState

```

### 5.4 状态枚举

建议统一：

```swift
enum ThemeSkinState: String, Codable {
    case `default`
```

## 6. 为“禁止跨主题混用”设计的数据模型

这是这次最关键的架构点。

### 6.1 商品模型

```swift
struct ThemeSkinProduct: Identifiable, Codable {
    let id: String
    let themeId: String
    let name: String
    let basePrice: Int
    let vipPrice: Int
    let previewImageNames: [String]
    let supportedSlots: [ThemeSkinSlot]
}
```

首套商品可定义为：

- `id = "theme_skin.girl_closet"`
- `basePrice = 99`
- `vipPrice = 89`

### 6.2 已购模型

```swift
struct OwnedThemeSkin: Identifiable, Codable {
    let id: String
    let purchasedAt: Date
    let paidPrice: Int
}
```

### 6.3 当前启用模型

```swift
struct ActiveThemeSkinSelection: Codable {
    var activeThemeId: String?
    var enabledSlots: Set<ThemeSkinSlot>
}
```

### 6.4 禁止混用规则

唯一合法来源：

- 当前所有主题组件，只允许从 `activeThemeId` 对应主题包中解析。

不合法情况：

- `topBar` 来自 `girl_closet`
- `tabBar` 来自 `rococo_boudoir`

因此渲染规则必须是：

1. 先读取 `activeThemeId`
2. 若为空，则全部回退系统默认皮肤
3. 若存在，则只允许从该主题包取样式
4. 对未启用 slot，回退“应用默认组件”，而不是回退到其他主题

这条规则可以天然杜绝混搭。

## 7. 建议的渲染层抽象

### 7.1 先做 Resolver，不要让业务页直接判断 themeId

建议新增：

```swift
protocol ThemeSkinProviding {
    func isSlotEnabled(_ slot: ThemeSkinSlot) -> Bool
    func activeThemeDescriptor(for slot: ThemeSkinSlot) -> ThemeSkinDescriptor?
}
```

```swift
struct ThemeSkinDescriptor: Codable {
    let themeId: String
    let slot: ThemeSkinSlot
    let assetNamespace: String
    let variant: String
}
```

### 7.2 业务层调用方式

业务页不再直接写：

- `if themeId == "girl_closet" { ... }`

统一改成：

- `themeSkinManager.descriptor(for: .topBarMain)`
- `themeSkinManager.descriptor(for: .tabBarMain)`
- `themeSkinManager.descriptor(for: .wardrobeItemCard)`

这样后续新增主题时不用改业务判断分支。
