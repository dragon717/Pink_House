# 特殊业务场景说明

## 1. 定金-尾款全生命周期管理

### 1.1 业务背景
三坑服饰通常采用“定金预售”模式，周期长（3个月至1年不等），流程复杂：
*   下单付定金 -> 等待制作 -> 尾款通知 -> 付尾款 -> 发货。

### 1.2 关键痛点与解决方案
*   **痛点**：尾款通知通常在私域（QQ群、微信群）或短信，容易被淹没。
*   **解决方案**：
    1.  **手动设定预计补款期**：录入定金时，强制或建议用户选择一个“预计补款月份”。
    2.  **智能倒计时**：首页展示“近期需补款”的物品。
    3.  **多级提醒**：
        *   T-7天：预提醒。
        *   T-1天：强提醒。
        *   T+0天：高亮显示。

### 1.3 状态机定义
*   `DepositPaid` (已付定金)：当前状态。
*   `BalancePending` (待补款)：进入补款期或用户标记为开始补款。
*   `PaidInFull` (已付全款)：尾款已结清。
*   `Shipped` (已发货)：物流运输中。
*   `Received` (已收货)：订单完成。
*   `Cancelled` (已跑单/定金作废)：特殊终止状态。

## 2. 补款提醒的时间触发机制

### 2.1 本地通知 (Local Notifications)
利用 `UserNotifications` 框架：
*   当用户设置了“预计补款日期”为 2026-05-01 时：
    *   注册 ID: `item_{uuid}_reminder_7d` (2026-04-24 10:00)
    *   注册 ID: `item_{uuid}_reminder_1d` (2026-04-30 10:00)

### 2.2 日历集成 (EventKit)
*   **功能**：一键将补款日程写入 iOS 系统日历。
*   **权限**：需请求日历读写权限。
*   **内容**：标题“【补款】XX裙装”，备注包含尾款金额。

## 3. 多件/多色/拼单管理
*   **场景**：用户一次性买了同一款裙装的不同颜色（双色入）。
*   **处理**：
    *   **方案 A**：作为两个独立 Item 录入（简单，推荐）。
    *   **方案 B**：一个 Item 下包含多个 SKU（复杂，暂不推荐用于 MVP 阶段）。
    *   **结论**：MVP 阶段建议用户录入两次，或提供“复制并新建”功能。

## 4. 汇率与代购费 (未来扩展)
*   若涉及日牌（日元）购买，需考虑汇率换算。
*   MVP 阶段统一以用户实际支付的“人民币”金额为准，不处理实时汇率。
